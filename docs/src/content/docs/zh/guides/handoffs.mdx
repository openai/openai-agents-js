交接让智能体能够将部分对话委托给另一个智能体。当不同智能体各有所长时，这会很有用。例如，在客户支持应用中，您可能会有分别处理预订、退款或常见问题的智能体。

交接以工具的形式呈现给 LLM。如果您交接给名为 `Refund Agent` 的智能体，工具名称将是 `transfer_to_refund_agent`。

> 阅读[智能体](/openai-agents-js/zh/guides/agents#composition-patterns)并确定应由专业智能体接管对话后，再阅读本页。如果专业智能体应在原智能体背后提供支持，请改用 [agents as tools](/openai-agents-js/zh/guides/tools#4-agents-as-tools)。

## 交接的创建

每个智能体都接受一个 `handoffs` 选项。它可以包含其他 `Agent` 实例，也可以包含由 `handoff()` 辅助函数返回的 `Handoff` 对象。

如果您直接传入 `Agent` 实例，其 `handoffDescription`（如果提供）会附加到默认工具描述中。可以用它来明确模型应在何时选择该交接。

### 通过 `handoff()` 自定义交接

`handoff()` 函数可让您调整生成的工具。

- `agent` – 要交接给的智能体。
- `toolNameOverride` – 覆盖默认的 `transfer_to_<agent_name>` 工具名称。
- `toolDescriptionOverride` – 覆盖默认的工具描述。
- `onHandoff` – 发生交接时的回调。接收一个 `RunContext`；配置了 `inputType` 时，还会接收解析后的交接载荷。
- `inputType` – 交接工具调用参数的模式。
- `inputFilter` – 过滤传递给下一个智能体的历史记录。
- `isEnabled` – 布尔值或谓词，仅在满足条件的运行中提供该交接。

`handoff()` 辅助函数始终将控制权转移给您传入的特定 `agent`。如果有多个可能的目标，请为每个目标注册一个交接，让模型从中选择。如果您自己的交接代码必须在调用时决定返回哪个智能体，请使用自定义 `Handoff`。

## 交接输入

有时，您希望模型在选择交接时附带一个小型结构化载荷。在这种情况下，请同时定义 `inputType` 和 `onHandoff`。

<Code lang="typescript" code={handoffInputExample} title="交接输入" />

`inputType` 描述交接工具调用本身的参数。SDK 将该模式作为交接工具的 `parameters` 提供给模型，在本地解析返回的参数，并将解析后的值传递给 `onHandoff`。

SDK 在准备提供给模型的可用交接时就会对 `isEnabled` 求值，此时模型尚未返回交接参数，因此它无法对带参数交接中的参数值进行授权检查。如果授权取决于解析后的字段，请在 `onHandoff` 开始时、任何应用副作用发生之前执行检查。如果授权失败，请抛出异常而不是返回；`onHandoff` 成功返回后，SDK 会继续执行交接。工具输入护栏适用于函数工具，不适用于交接。

它不会替换下一个智能体的主要输入，也不会选择不同的目标。`handoff()` 辅助函数仍会将控制权转移给您封装的特定智能体，而接收交接的智能体仍会看到对话历史记录，除非您使用 `inputFilter` 对其进行修改。

`inputType` 也独立于 `RunContext`。请将它用于模型在交接时决定的元数据，而不是您在本地已有的应用状态或依赖项。

### `inputType` 的适用场景

当交接需要少量由模型生成的路由元数据（例如 `reason`、`language`、`priority` 或 `summary`）时，请使用 `inputType`。例如，分流智能体可以携带 `{ reason: 'duplicate_charge', priority: 'high' }` 交接给退款智能体，而 `onHandoff` 可以在退款智能体接管之前记录或持久化这些元数据。

如果目标不同，请选择其他机制：

- 将现有应用状态放入 `RunContext`。
- 如果您想更改接收交接的智能体所看到的历史记录，请使用 `inputFilter`。
- 如果有多个可能的专业智能体，请为每个目标注册一个交接。`inputType` 可以为所选交接添加元数据，但不会在不同目标之间进行分派。
- 如果您希望 SDK 在 `onHandoff` 运行前验证解析后的载荷，请优先使用 Zod 模式或受支持的 Standard Schema 值；原始 JSON Schema 仅定义发送给模型的工具契约。有关 Standard Schema 的示例，请参阅[模式验证](/openai-agents-js/zh/guides/schemas)。

## 输入过滤器

默认情况下，交接会接收完整的对话历史记录。要修改传递给下一个智能体的内容，请提供 `inputFilter`。常用辅助函数位于 `@openai/agents-core/extensions` 中。

<Code lang="typescript" code={inputFilterExample} title="输入过滤器" />

`inputFilter` 接收并返回一个 `HandoffInputData` 对象：

- `inputHistory` – 运行开始前的输入历史记录。
- `preHandoffItems` – 在发生交接的轮次之前生成的条目。
- `newItems` – 当前轮次中生成的条目，包括交接调用和输出条目。
- `runContext` – 当前活动的运行上下文。

如果您还在 `Runner` 上配置了 `handoffInputFilter`，则对于特定交接，其自身的 `inputFilter` 优先。

<Aside type="note">
  交接始终在单次运行内进行。输入护栏仍然只适用于
  链中的第一个智能体，输出护栏则只适用于
  生成最终输出的智能体。如果需要在工作流中
  每次自定义函数工具调用前后进行检查，请使用工具护栏。
</Aside>
