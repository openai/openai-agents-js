Agents SDK 可以逐步交付模型及其他执行步骤的输出。流式传输让 UI 保持响应，无需等待完整的最终结果就能向用户提供更新。

## 流式传输的启用

向 `Runner.run()` 传入 `{ stream: true }` 选项，即可获得流式对象，而不是完整的执行结果：

<Code lang="typescript" code={basicStreamingExample} title="启用流式传输" />

启用流式传输后，返回的 `stream` 实现了 `AsyncIterable` 接口。每个产出的事件都是一个对象，用于描述运行过程中发生的情况。流会产出三种事件类型之一，每种类型描述智能体执行的不同部分。不过，大多数应用只需要模型的文本，因此流提供了一些辅助方法。

### 获取文本输出

调用 `stream.toTextStream()` 可获取输出文本的流。当 `compatibleWithNodeStreams` 为 `true` 时，返回值是常规的 Node.js `Readable`。我们可以将其直接通过管道传输到 `process.stdout` 或其他目标。

当运行和所有待处理的回调都完成后，`stream.completed` 这个 Promise 才会兑现。如果要确保没有更多输出，请务必等待它。这也包括在最后一个文本 token 到达后才完成的后处理工作，例如会话持久化或历史记录压缩钩子。

`toTextStream()` 仅输出助手文本。工具调用、交接、审批和其他运行时事件可从完整的事件流中获取。

### Responses WebSocket 传输机制（可选）

本页介绍的流式传输 API 也适用于 OpenAI Responses WebSocket 传输机制。

可以通过 `setOpenAIResponsesTransport('websocket')` 全局启用，也可以使用自行创建的 `OpenAIProvider` 并设置 `useResponsesWebSocket: true`。

如果只是通过 WebSocket 进行流式传输，则不需要 `withResponsesWebSocketSession(...)` 或自定义的 `OpenAIProvider`。如果可以接受在每次运行之间重新连接，那么启用该传输机制后，`run()` / `Runner.run(..., { stream: true })` 仍然可用。

如果需要复用连接，并更明确地控制提供方的生命周期，请使用 `withResponsesWebSocketSession(...)` 或自定义的 `OpenAIProvider` / `Runner`。

使用 `previousResponseId` 继续运行时，其语义与 HTTP 传输机制相同。区别仅在于传输机制和连接生命周期。

如果自行构建提供方，请记得在关闭时调用 `await provider.close()`。基于 WebSocket 的模型封装默认会被缓存以供复用，关闭提供方会释放这些连接。`withResponsesWebSocketSession(...)` 提供相同的复用能力，但会自动将清理操作限定在单个回调的作用域内。

请参阅 [`examples/basic/stream-ws.ts`](https://github.com/openai/openai-agents-js/tree/main/examples/basic/stream-ws.ts)，其中提供了包含流式传输、工具调用、审批和 `previousResponseId` 的完整代码示例。

## 流式传输中的人工干预

流式传输兼容会暂停执行的交接（例如工具需要审批时）。流对象上的 `interruptions` 字段会提供待处理的审批，您可以对每项审批调用 `state.approve()` 或 `state.reject()`，以继续执行。流暂停后，`stream.completed` 会兑现，`stream.interruptions` 则包含需要处理的审批。再次使用 `{ stream: true }` 执行即可恢复流式输出。

## 流式传输的停止与同一轮次的继续

要提前停止流式运行，可以中止传给 `run()` 的 `signal`，或取消从 `stream.toStream()` 创建的读取器。无论采用哪种方式，都仍需等待 `stream.completed`，才能将本次运行视为已结束。在代码停止消费事件后，SDK 可能仍在持久化当前轮次的输入，或完成其他清理工作。

流被取消后，`stream.cancelled` 会变为 `true`，而 `stream.finalOutput` 通常仍为 `undefined`，因为当前轮次尚未完成。如果希望稍后继续这个未完成的轮次，请使用 `stream.state` 重新运行同一个智能体，而不是追加一条新的用户消息。这样可以保持轮次计数正确，并复用已存储在 `RunState` 中的 `conversationId` 或 `previousResponseId`。

如果还使用了会话持久化，请在恢复执行的 `run()` 调用中再次传入相同的 `session`，以便对话继续写入同一个后端存储。

审批暂停也遵循相同规则：处理 `stream.interruptions`，然后从 `stream.state` 恢复，而不是开始新一轮。

## 提示

- 请记得在退出前等待 `stream.completed`，以确保所有输出均已刷新。
- 最初的 `{ stream: true }` 选项仅适用于传入该选项的那次调用。如果使用 `RunState` 重新运行，必须再次指定此选项。
- 如果应用只关心文本结果，建议使用 `toTextStream()`，以避免处理单个事件对象。

借助流式传输和事件系统，您可以将智能体集成到聊天界面、终端应用或任何能让用户受益于增量更新的场景中。
