[**Model Context Protocol (MCP)**](https://modelcontextprotocol.io) 是一种开放协议，用于标准化应用向 LLM 提供工具和上下文的方式。以下内容摘自 MCP 文档：

> MCP 是一种开放协议，用于标准化应用向 LLM 提供上下文的方式。可以将 MCP 视为 AI 应用的 USB-C 端口。正如 USB-C 提供了一种将设备连接到各种外设和配件的标准化方式，MCP 也提供了一种将 AI 模型连接到不同数据源和工具的标准化方式。

此 SDK 支持三种类型的 MCP 服务器：

1. **远程 MCP 服务器工具**——由 [OpenAI Responses API](https://platform.openai.com/docs/guides/tools-remote-mcp) 作为工具使用的远程 MCP 服务器
2. **Streamable HTTP MCP 服务器**——实现 [Streamable HTTP 传输](https://modelcontextprotocol.io/docs/concepts/transports#streamable-http)的本地或远程服务器
3. **Stdio MCP 服务器**——通过标准输入/输出访问的服务器（最简单的选项）

> 注意：SDK 还提供了 `MCPServerSSE`，用于旧版服务器发送事件（Server-Sent Events）传输，但 MCP 项目已弃用 SSE。对于新的集成，请优先选择 Streamable HTTP 或 stdio。

请根据使用场景选择服务器类型：

| 需求 | 推荐选项 |
| --- | --- |
| 使用默认的 OpenAI Responses 模型调用可公开访问的远程服务器 | **1. 托管 MCP 工具** |
| 使用可公开访问的远程服务器，但在本地触发工具调用 | **2. Streamable HTTP** |
| 使用在本地运行的 Streamable HTTP 服务器 | **2. Streamable HTTP** |
| 使用非 OpenAI Responses 模型访问任意 Streamable HTTP 服务器 | **2. Streamable HTTP** |
| 使用仅支持标准 I/O 协议的本地 MCP 服务器 | **3. Stdio** |

## MCP SDK v2 与 v1 服务器的兼容性

Agents SDK 在内部使用 MCP TypeScript SDK v2 客户端。这并不要求您的 MCP 服务器迁移到 v2 服务器包。对于 stdio 和 Streamable HTTP 连接，Agents SDK 会自动协商协议，并与使用 MCP TypeScript SDK v1 实现的现有服务器保持兼容，前提是这些服务器支持兼容的协议版本。

如果您的应用仅使用 Agents SDK 的 `MCPServerStdio`、`MCPServerStreamableHttp` 或 `MCPServerSSE` 类，则无需安装或桥接 MCP v1 和 v2 包即可实现这种兼容性。当您希望采用 v2 MCP SDK API 时，请单独迁移应用自身使用的 MCP SDK 对象；参阅 MCP TypeScript SDK 的 [v1 到 v2 迁移指南](https://github.com/modelcontextprotocol/typescript-sdk/blob/main/docs/migration/upgrade-to-v2.md)。

### 托管 MCP 选项参考

`hostedMcpTool(...)` 同时支持 MCP 服务器 URL 和基于连接器的服务器：

| 选项 | 类型 | 说明 |
| --- | --- | --- |
| `serverLabel` | `string` | 必填标签，用于在事件和追踪中标识托管 MCP 服务器。 |
| `serverUrl` | `string` | 远程 MCP 服务器 URL（用于常规托管 MCP 服务器）。 |
| `connectorId` | `string` | OpenAI 连接器 ID（对于基于连接器的托管服务器，使用此项代替 `serverUrl`）。 |
| `authorization` | `string` | 可选的授权令牌，发送到托管 MCP 后端。 |
| `headers` | `Record<string, string>` | 可选的额外请求头。 |
| `allowedTools` | `string[] \| object` | 向模型公开的工具名称允许列表。传入 `string[]` 或 `{ toolNames?: string[] }`。 |
| `allowedCallers` | `('direct' \| 'programmatic')[]` | 仅适用于 Responses 的非空列表，用于控制托管 MCP 工具能否被直接调用、通过编程式工具调用来调用，或同时支持这两种方式。 |
| `deferLoading` | `boolean` | 仅适用于 Responses 的托管 MCP 工具延迟加载。要求同一智能体中包含 `toolSearchTool()`。 |
| `requireApproval` | `'never' \| 'always' \| object` | 托管 MCP 工具调用的审批策略。使用对象形式可按工具覆盖策略。默认为 `'never'`。 |
| `onApproval` | 审批回调 | 可选回调，用于在 `requireApproval` 要求进行审批处理时，以编程方式批准或拒绝调用。 |

如果希望模型通过工具搜索按需加载托管 MCP 服务器的工具定义，而不是预先公开这些定义，请设置 `deferLoading: true`。此功能仅适用于 OpenAI Responses API，要求同一请求中包含 `toolSearchTool()`，并且应与 GPT-5.4 及更新的受支持模型版本配合使用。完整的延迟加载配置请参阅[工具](/openai-agents-js/zh/guides/tools#deferred-tool-loading-with-tool-search)指南。

如果托管 MCP 工具只应由模型生成的 JavaScript 调用，请设置 `allowedCallers: ['programmatic']`；也可以同时包含 `'direct'` 和 `'programmatic'`，以允许这两种调用方式。请在同一智能体中添加 `programmaticToolCallingTool()`。程序调用 MCP 工具时，现有的 `requireApproval` 和 `onApproval` 策略仍然适用。完整配置请参阅[编程式工具调用](/openai-agents-js/zh/guides/tools#programmatic-tool-calling)。

`requireApproval` 的对象形式接受可选的 `always` 和 `never` 条目。每个条目都可以通过 `toolNames` 或工具的只读注解来选择工具。可选的 `onApproval` 回调会接收当前运行上下文和审批项，然后返回一个 Promise，其结果包含 `approve` 和可选的 `reason`。

注意事项：

- `convertSchemasToStrict` 会尽力进行转换。如果无法转换某个模式，则使用原始模式。
- `errorFunction` 控制向模型呈现 MCP 工具调用失败的方式。
- 未设置 `errorFunction` 时，SDK 使用默认的工具错误格式化函数。
- 服务器级别的 `errorFunction` 值会覆盖该服务器的 `Agent.mcpConfig.errorFunction`。
- `includeServerInToolNames` 需要显式启用。启用后，每个本地 MCP 工具都会以带有确定性服务器前缀的名称向模型公开，有助于避免多个 MCP 服务器发布同名工具时出现冲突。
- SDK 会先从基于 URL 生成的服务器名称和传输错误中移除 URL 凭据、查询参数和片段，再通过日志、追踪和错误消息公开这些信息。如果需要稳定的服务器标签，请显式设置一个唯一且不含机密信息的 `name`。
- 如果不同的 URL 所生成的服务器名称在移除凭据、查询参数和片段后变得相同，并且这些服务器发布了同名工具，配置会在向模型发送请求之前失败。请为这些服务器显式设置唯一且不含机密信息的 `name` 值。

## MCP 服务器生命周期管理

使用多个 MCP 服务器时，您可以使用 `connectMcpServers` 集中连接这些服务器、追踪失败情况并关闭连接。此辅助函数返回一个包含 `active`、`failed` 和 `errors` 集合的 `MCPServers` 实例，以便您仅将正常可用的服务器传递给智能体。

<Code lang="typescript" code={mcpServersExample} title="管理多个 MCP 服务器" />

使用场景：

- **同时连接多个服务器**：并行连接所有服务器，并为智能体使用 `mcpServers.active`。
- **部分失败处理**：检查 `failed` 和 `errors`，决定继续还是重试。
- **重试失败的服务器**：调用 `mcpServers.reconnect()`（默认仅重试失败的服务器）。

如果需要严格的"全部成功或全部失败"连接模式，或需要设置不同的超时时间，请使用 `connectMcpServers(servers, options)`，并根据您的环境调整选项。

`connectMcpServers` 选项：

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `connectTimeoutMs` | `number \| null` | `10000` | 每个服务器执行 `connect()` 的超时时间。使用 `null` 可禁用超时。 |
| `closeTimeoutMs` | `number \| null` | `10000` | 每个服务器执行 `close()` 的超时时间。使用 `null` 可禁用超时。 |
| `dropFailed` | `boolean` | `true` | 从 `active` 中排除失败的服务器。 |
| `strict` | `boolean` | `false` | 任何服务器连接失败时抛出异常。 |
| `suppressAbortError` | `boolean` | `true` | 忽略中止类错误，但仍追踪失败的服务器。 |
| `connectInParallel` | `boolean` | `false` | 并发而非依次连接所有服务器。 |

`mcpServers.reconnect(options)` 支持：

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `failedOnly` | `boolean` | `true` | 仅重试失败的服务器（`true`），或重新连接所有服务器（`false`）。 |

重新连接之前，`MCPServers` 会关闭选中的服务器。它仅重新连接已成功关闭的服务器；清理失败的信息仍可通过 `failed` 和 `errors` 获取。

## 其他注意事项

对于 **Streamable HTTP** 和 **Stdio** 服务器，`Agent` 每次运行时都可能调用 `list_tools()` 来发现可用工具。由于这种往返调用可能增加延迟，尤其是在访问远程服务器时，您可以通过向 `MCPServerStdio` 或 `MCPServerStreamableHttp` 传入 `cacheToolsList: true`，将结果缓存在内存中。

请仅在确定工具列表不会变化时启用此功能。若之后需要使缓存失效，请在服务器实例上调用 `invalidateToolsCache()`。如果您通过 `getAllMcpTools(...)` 使用共享 MCP 工具缓存，也可以通过 `invalidateServerToolsCache(serverName)` 按服务器名称使缓存失效。

对于高级场景，`getAllMcpTools({ generateMCPToolCacheKey })` 允许您自定义缓存分区方式（例如，按服务器 + 智能体 + 运行上下文分区）。

### 带服务器前缀的工具名称

默认情况下，本地 MCP 工具保留 MCP 服务器报告的工具名称。如果两个本地 MCP 服务器公开了同名工具，SDK 会引发工具名称重复错误，因为模型无法在两者之间安全地做出选择。
