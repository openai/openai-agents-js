[**Model Context Protocol (MCP)**](https://modelcontextprotocol.io) 是一个开放协议，用于标准化应用向 LLM 提供工具和上下文的方式。根据 MCP 文档：

> MCP 是一个开放协议，用于标准化应用向 LLM 提供上下文的方式。您可以将 MCP 视为 AI 应用的 USB-C 端口。正如 USB-C 提供了一种标准化方式，将设备连接到各种外围设备和配件，MCP 也提供了一种标准化方式，将 AI 模型连接到不同的数据源和工具。

此 SDK 支持三种类型的 MCP 服务器：

1. **远程 MCP 服务器工具**——由 [OpenAI Responses API](https://platform.openai.com/docs/guides/tools-remote-mcp) 用作工具的远程 MCP 服务器
2. **可流式传输的 HTTP MCP 服务器**——实现[可流式传输 HTTP 传输机制](https://modelcontextprotocol.io/docs/concepts/transports#streamable-http)的本地或远程服务器
3. **Stdio MCP 服务器**——通过标准输入/输出访问的服务器（最简单的选项）

> 注意：SDK 还包含用于旧版服务器发送事件传输机制的 `MCPServerSSE`，但 MCP 项目已弃用 SSE。对于新的集成，请优先使用可流式传输的 HTTP 或 stdio。

请根据您的用例选择服务器类型：

| 您的需求 | 推荐选项 |
| --- | --- |
| 使用默认 OpenAI Responses 模型调用可公开访问的远程服务器 | **1. 远程 MCP 工具** |
| 使用可公开访问的远程服务器，但在本地触发工具调用 | **2. 可流式传输的 HTTP** |
| 使用本地运行的可流式传输 HTTP 服务器 | **2. 可流式传输的 HTTP** |
| 将任意可流式传输 HTTP 服务器与非 OpenAI Responses 模型搭配使用 | **2. 可流式传输的 HTTP** |
| 使用仅支持标准 I/O 协议的本地 MCP 服务器 | **3. Stdio** |

## MCP SDK v2 与 v1 服务器兼容性

Agents SDK 在内部使用 MCP TypeScript SDK v2 客户端。这并不要求您的 MCP 服务器迁移到 v2 服务器软件包。对于 stdio 和可流式传输 HTTP 连接，Agents SDK 会自动协商协议，并继续兼容使用 MCP TypeScript SDK v1 实现且支持兼容协议版本的现有服务器。

如果您的应用仅使用 Agents SDK 的 `MCPServerStdio`、`MCPServerStreamableHttp` 或 `MCPServerSSE` 类，则无需为实现这种兼容性而安装或桥接 MCP v1 和 v2 软件包。如果您希望采用 v2 MCP SDK API，请单独迁移由应用自行管理的 MCP SDK 对象；请参阅 MCP TypeScript SDK 的 [v1 到 v2 迁移指南](https://github.com/modelcontextprotocol/typescript-sdk/blob/main/docs/migration/upgrade-to-v2.md)。

### 远程 MCP 选项参考

`hostedMcpTool(...)` 同时支持 MCP 服务器 URL 和由连接器支持的服务器：

| 选项 | 类型 | 说明 |
| --- | --- | --- |
| `serverLabel` | `string` | 必填标签，用于在事件和追踪中标识远程 MCP 服务器。 |
| `serverUrl` | `string` | 远程 MCP 服务器 URL（用于常规的远程 MCP 服务器）。 |
| `connectorId` | `string` | OpenAI 连接器 ID（对于由连接器支持的托管服务器，请使用此选项代替 `serverUrl`）。 |
| `authorization` | `string` | 可选的授权令牌，将发送到托管 MCP 后端。 |
| `headers` | `Record<string, string>` | 可选的额外请求标头。 |
| `allowedTools` | `string[] \| object` | 向模型公开的工具名称允许列表。传入 `string[]` 或 `{ toolNames?: string[] }`。 |
| `allowedCallers` | `('direct' \| 'programmatic')[]` | 仅适用于 Responses API 的非空列表，用于控制远程 MCP 工具能否直接调用、通过编程式工具调用，或通过这两种方式调用。 |
| `deferLoading` | `boolean` | 仅适用于 Responses API 的远程 MCP 工具延迟加载。同一智能体中必须包含 `toolSearchTool()`。 |
| `requireApproval` | `'never' \| 'always' \| object` | 远程 MCP 工具调用的审批策略。使用对象形式可对各个工具进行覆盖。默认为 `'never'`。 |
| `onApproval` | 审批回调 | 可选回调，用于在 `requireApproval` 要求处理审批时，以编程方式批准或拒绝调用。 |

如果您希望模型通过工具搜索按需加载远程 MCP 服务器的工具定义，而不是预先公开这些定义，请设置 `deferLoading: true`。此功能仅适用于 OpenAI Responses API，要求同一请求中包含 `toolSearchTool()`，并且应搭配 GPT-5.4 及更新的受支持模型版本使用。有关完整的延迟加载设置，请参阅[工具](/openai-agents-js/zh/guides/tools#deferred-tool-loading-with-tool-search)。

如果远程 MCP 工具只能从模型生成的 JavaScript 中调用，请设置 `allowedCallers: ['programmatic']`；若要允许任一路径，请同时包含 `'direct'` 和 `'programmatic'`。请将 `programmaticToolCallingTool()` 添加到同一智能体。当程序调用 MCP 工具时，现有的 `requireApproval` 和 `onApproval` 策略仍然适用。有关完整设置，请参阅[编程式工具调用](/openai-agents-js/zh/guides/tools#programmatic-tool-calling)。

`requireApproval` 的对象形式接受可选的 `always` 和 `never` 条目。每个条目都可以使用 `toolNames` 或工具的只读注解来选择工具。可选的 `onApproval` 回调接收当前运行上下文和审批项，然后返回一个 Promise，其中包含 `approve` 和可选的 `reason`。

注意事项：

- `convertSchemasToStrict` 会尽力完成转换。如果无法转换某个架构，则使用原始架构。
- `errorFunction` 控制如何向模型呈现 MCP 工具调用失败。
- 未设置 `errorFunction` 时，SDK 使用默认的工具错误格式化程序。
- 对于相应服务器，服务器级 `errorFunction` 值会覆盖 `Agent.mcpConfig.errorFunction`。
- `includeServerInToolNames` 需要显式启用。启用后，每个本地 MCP 工具都会使用带有确定性服务器前缀的名称向模型公开，这有助于避免多个 MCP 服务器发布同名工具时发生冲突。
- 在通过日志、追踪和错误消息公开由 URL 派生的服务器名称和传输错误之前，SDK 会移除 URL 凭据、查询参数和片段。如果需要稳定的服务器标签，请设置明确、唯一且不包含机密信息的 `name`。
- 如果不同的 URL 派生服务器名称在移除凭据、查询参数和片段后变得相同，并且它们发布了同名工具，则配置会在模型请求之前失败。请为这些服务器设置明确、唯一且不包含机密信息的 `name` 值。

## MCP 服务器生命周期管理

使用多个 MCP 服务器时，您可以使用 `connectMcpServers` 同时连接这些服务器、追踪失败情况并集中关闭它们。该辅助函数返回一个包含 `active`、`failed` 和 `errors` 集合的 `MCPServers` 实例，因此您可以仅将健康的服务器传给智能体。

<Code lang="typescript" code={mcpServersExample} title="管理多个 MCP 服务器" />

用例：

- **同时使用多个服务器**：并行连接所有服务器，并将 `mcpServers.active` 用于智能体。
- **处理部分失败**：检查 `failed` + `errors`，并决定继续还是重试。
- **重试失败的服务器**：调用 `mcpServers.reconnect()`（默认仅重试失败的服务器）。

如果您希望采用严格的"全有或全无"连接方式或设置不同的超时时间，请使用 `connectMcpServers(servers, options)`，并根据您的环境调整选项。

`connectMcpServers` 选项：

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `connectTimeoutMs` | `number \| null` | `10000` | 每个服务器 `connect()` 的超时时间。使用 `null` 可禁用。 |
| `closeTimeoutMs` | `number \| null` | `10000` | 每个服务器 `close()` 的超时时间。使用 `null` 可禁用。 |
| `dropFailed` | `boolean` | `true` | 从 `active` 中排除连接失败的服务器。 |
| `strict` | `boolean` | `false` | 任意服务器连接失败时抛出异常。 |
| `suppressAbortError` | `boolean` | `true` | 忽略类似中止的错误，同时仍追踪连接失败的服务器。 |
| `connectInParallel` | `boolean` | `false` | 并发连接所有服务器，而不是依次连接。 |

`mcpServers.reconnect(options)` 支持：

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `failedOnly` | `boolean` | `true` | 仅重试失败的服务器（`true`），或重新连接所有服务器（`false`）。 |

重新连接前，`MCPServers` 会关闭选定的服务器。它只会重新连接成功关闭的服务器；清理失败信息仍可通过 `failed` 和 `errors` 获取。

## 其他注意事项

对于**可流式传输的 HTTP** 和 **Stdio** 服务器，每次 `Agent` 运行时，都可能调用 `list_tools()` 来发现可用工具。由于这种往返可能增加延迟，尤其是对于远程服务器，因此可以向 `MCPServerStdio` 或 `MCPServerStreamableHttp` 传入 `cacheToolsList: true`，在内存中缓存结果。

仅当您确信工具列表不会更改时才启用此功能。若要稍后使缓存失效，请在服务器实例上调用 `invalidateToolsCache()`。如果您通过 `getAllMcpTools(...)` 使用共享 MCP 工具缓存，也可以使用 `invalidateServerToolsCache(serverName)` 按服务器名称使缓存失效。

对于高级用例，`getAllMcpTools({ generateMCPToolCacheKey })` 允许您自定义缓存分区方式，例如按服务器、智能体和运行上下文进行分区。

### 带服务器前缀的工具名称

默认情况下，本地 MCP 工具会保留 MCP 服务器报告的工具名称。如果两个本地 MCP 服务器公开了同名工具，SDK 会引发工具名称重复错误，因为模型无法安全地在两者之间进行选择。

若要启用带有确定性服务器前缀的名称，请在智能体上设置 `mcpConfig.includeServerInToolNames: true`：

<Code
  lang="typescript"
  code={serverPrefixedToolNamesExample}
  title="为本地 MCP 工具名称添加服务器名称前缀"
/>

启用此设置后，来自 `docs` 服务器的 `search` 工具会以 `mcp_docs__search` 的名称向模型公开，而来自 `calendar` 服务器的 `search` 工具则会以 `mcp_calendar__search` 的名称公开。SDK 仍会在原始服务器上调用原始 MCP 工具名称。

生成的名称可安全用于 ASCII，且不会超过 `FunctionTool` 实例的名称长度限制，也不会与同一智能体上的本地 `FunctionTool` 实例名称或已启用的交接名称冲突。此设置会影响所有本地 MCP 传输机制，包括可流式传输的 HTTP、SSE 和 stdio；远程 MCP 工具会保留其托管服务器标签和工具元数据。
