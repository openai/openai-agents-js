## Project setup and credentials

<Steps>

1. **Create a project**

   Create a voice agent that runs in the browser. To start a new project, use [`Next.js`](https://nextjs.org/docs/getting-started/installation) or [`Vite`](https://vite.dev/guide/installation.html).

   ```bash
   npm create vite@latest my-project -- --template vanilla-ts
   ```

2. **Install the SDK**

   Run `cd my-project` and [install the alpha SDK](https://github.com/openai/openai-agents-js/blob/feat/codex-harness/packages/agents/examples/guides/installation.md#add-the-sdk-to-an-existing-application) to use the classic Realtime imports below. Then install Zod 4.

   ```bash
   npm install zod@4
   ```

3. **Generate a client ephemeral token**

   This browser application needs a secure connection to the model through the Realtime API. The recommended flow matches the official [Realtime API with WebRTC](https://developers.openai.com/api/docs/guides/realtime-webrtc/) guide: your backend creates a short-lived ephemeral client token, then your browser uses that token to establish the WebRTC connection. For testing, you can also generate a token with `curl` and your regular OpenAI API key.

   ```bash
   export OPENAI_API_KEY="sk-proj-...(your own key here)"
   curl -X POST https://api.openai.com/v1/realtime/client_secrets \
      -H "Authorization: Bearer $OPENAI_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "session": {
          "type": "realtime",
          "model": "gpt-realtime-2.1"
        }
      }'
   ```

   The response contains a top-level `value` field that starts with the `ek_` prefix, plus the effective `session` object. Use `value` as the client secret when establishing the WebRTC connection. This token is short-lived, so your backend should mint a fresh one when needed. If your browser session needs hosted MCP tools with `authorization` or custom `headers`, include that hosted MCP configuration in the server-side `session` payload you send to `POST /v1/realtime/client_secrets` instead of exposing those credentials in browser code.

</Steps>

<Aside type="note">
  Production browser flow: the browser asks your backend for a fresh ephemeral
  token, your backend calls `POST /v1/realtime/client_secrets` with a server API
  key, and the browser passes the returned `ek_...` token to
  `session.connect(...)`.
</Aside>

## Create and connect the voice agent

<Steps>

1. **Create your first Agent**

   Creating a [`RealtimeAgent`](/openai-agents-js/openai/agents-realtime/classes/realtimeagent/) is similar to creating a regular [`Agent`](/openai-agents-js/guides/agents).

   ```typescript
   import { RealtimeAgent } from '@openai/agents/realtime';

   const agent = new RealtimeAgent({
     name: 'Assistant',
     instructions: 'You are a helpful assistant.',
   });
   ```

2. **Create a session**

   A voice agent runs continuously inside a `RealtimeSession`, which manages the conversation and model connection over time. The session also manages audio processing, interruptions, and the conversation lifecycle.

   ```typescript
   import { RealtimeSession } from '@openai/agents/realtime';

   const session = new RealtimeSession(agent, {
     model: 'gpt-realtime-2.1',
   });
   ```

   The `RealtimeSession` constructor takes an `agent` as the first argument. The user interacts with this agent first.

3. **Connect to the session**

   Connect to the session with the client ephemeral token you generated earlier.

   ```typescript
   await session.connect({ apiKey: 'ek_...(put your own key here)' });
   ```

   In the browser, this connects to the Realtime API using WebRTC and automatically configures microphone capture and audio playback for you. On the default WebRTC path, the SDK sends the initial session configuration as soon as the data channel opens. It tries to wait for the matching `session.updated` acknowledgement before `connect()` resolves, with a timeout fallback if the acknowledgement never arrives. If you run `RealtimeSession` in a server runtime such as Node.js, the SDK automatically falls back to WebSocket instead; on the WebSocket path, `connect()` resolves after the socket opens and the initial config has been sent, so `session.updated` may arrive slightly later. You can learn more about the transport choices in the [Realtime Transport Layer](/openai-agents-js/guides/voice-agents/transport) guide.

</Steps>

<Aside type="note">
  This quickstart uses the shortest path to get a browser voice agent running:
  `RealtimeSession` runs in the browser, and the built-in WebRTC transport uses
  a data channel for Realtime events. If the browser should carry only audio
  while an application server owns Realtime events, tools, and business logic,
  see [Browser audio with server-side
  controls](/openai-agents-js/guides/voice-agents/transport#browser-audio-with-server-side-controls).
  For lower-level browser control, see the [`/raw-client` example in
  `examples/realtime-next`](https://github.com/openai/openai-agents-js/tree/main/examples/realtime-next).
</Aside>
