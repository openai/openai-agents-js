This page covers **SDK-wide defaults** you usually set once at app startup: the OpenAI client, transport, tracing export key, and debug logging behavior. These settings apply across the process by default.

To configure a specific `Agent`, `Runner`, or `run()` call, see:

- [Running Agents](/openai-agents-js/guides/running-agents) for `Runner` and per-run options.
- [Models](/openai-agents-js/guides/models) for agent-level and runner-level model settings.
- [Tracing](/openai-agents-js/guides/tracing) for run-specific tracing configuration and exporter behavior.

### Responses transport

With the Responses API, you can choose the OpenAI provider transport. The default is HTTP.

<Code
  lang="typescript"
  code={setOpenAIResponsesTransportExample}
  title="Set Responses transport"
/>

Use `setOpenAIResponsesTransport('websocket')` to enable the WebSocket transport and `setOpenAIResponsesTransport('http')` to switch back. If you route websocket traffic through a proxy or gateway, set `OPENAI_WEBSOCKET_BASE_URL` (or configure `websocketBaseURL` on your `OpenAIProvider`).

This process-wide default only affects models that are later resolved through the default OpenAI provider. If you pass a concrete `Model` instance or a custom `modelProvider`, configure the transport there instead. See the [Models guide](/openai-agents-js/guides/models#responses-websocket-transport).

### Debug logging

The SDK uses the [`debug`](https://www.npmjs.com/package/debug) package for debug logging. Set the `DEBUG` environment variable to `openai-agents*` to see verbose logs.

```bash
export DEBUG=openai-agents*
```

To log session persistence activity, set `OPENAI_AGENTS__DEBUG_SAVE_SESSION=1`.

Use `getLogger(namespace)` from `@openai/agents` to get a namespaced logger for your modules.

#### Sensitive data in logs

By default, logs exclude model and tool data, including related error objects and details. To include those details while debugging, enable sensitive data logging for the process:

<Code
  lang="typescript"
  code={setSensitiveDataLoggingEnabledExample}
  title="Enable sensitive data logging"
/>

Only enable this in an environment where logs are handled securely. The programmatic setting controls both model and tool data and takes precedence over the environment variables below. Call `setSensitiveDataLoggingEnabled(false)` to disable sensitive data logging again.

You can also opt in to model and tool data independently with environment variables. Set the corresponding `OPENAI_AGENTS_DONT_LOG_*` variable to `0` or `false`:

```bash
export OPENAI_AGENTS_DONT_LOG_MODEL_DATA=0
export OPENAI_AGENTS_DONT_LOG_TOOL_DATA=0
```

Setting either variable to `1` or `true` keeps the corresponding data and related error details redacted. Unset or unrecognized values also use the secure default and keep sensitive data out of logs.
