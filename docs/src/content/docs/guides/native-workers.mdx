Run each worker in its own process with a workspace and a local profile for conversation history. The worker owns the live `Session` and its `Turn` handles. The supervisor reads progress from the application journal. Save `session.id` so a replacement worker can reopen the same conversation.

Use Node.js 24 and build the SDK and matching native runtime from the `feat/codex-harness` checkout for these worker controls. Live model calls need an API key. The runnable example uses scripted responses. [Build from source](https://github.com/openai/openai-agents-js/blob/feat/codex-harness/packages/agents-codex/examples/guides/building.md) or [run the reference worker](#run-the-reference-worker).

## Choose what the worker can do

Open the session with `agent.session({ environment, storage })`. Create `storage` with `localStorage(path)` and choose both paths in trusted application code. Keep the profile and the application journal outside the executor working directory and every additional writable root, including roots granted on later turns. Let only one worker write to a conversation at a time.

### Open a local executor

Use `Environment.local({ cwd, tools, writableRoots })` on Linux or macOS. Select the tools the worker needs from `exec_command`, `write_stdin`, and `apply_patch`. The session opens only if the platform sandbox starts. On macOS, the host also needs a per-user `launchd` domain and support for signaling processes by identity.

The workspace and any extra writable roots must resolve to existing directories below the executor's filesystem root. The workspace (`cwd`) is always writable. The sandbox protects metadata inside those roots. If a command needs temporary storage, use a directory within a writable root.

The local sandbox lets commands read the workspace, extra writable roots, and the platform files and helpers needed to run the sandbox. The executor starts each command with a fresh environment and sets `PATH` to `/usr/bin:/bin`. Install the SDK and its native helpers outside every writable root. For example, install the SDK in the supervisor's project and give the worker a separate workspace.

The local executor uses restricted networking by default. Set `network` to configure its managed proxy for `exec_command`. Your application's JavaScript and MCP clients use their own process permissions.

### Change write access between turns

On a supported Linux executor or the bundled local macOS executor, a new root submission can replace the extra writable roots.

1. Wait for the current root turn to finish, or cancel it and await cleanup. Collect results from any yielded tool cells or returned process handles.
2. For a new or previously removed directory, use the canonical executor path from your application's configuration. If a current root uses a symlink, that path must still resolve to the same directory.
3. Call `session.submit(input, { writableRoots })`. Pass `[]` to allow writes only in the workspace. Omit `writableRoots` to keep the current policy.

For a WSS executor that reports macOS, choose the write roots when opening the session. A later submission can repeat an equivalent grant if the paths pass validation.

### Connect a remote executor

For a WSS executor, select the endpoint and credentials in trusted code. Set `writableRoots` on the environment to require the strict write policy. The SDK checks the capabilities that the executor reports. The application must trust that executor to enforce the policy. Read the startup error to distinguish a refused connection, a timeout, or denied authentication. Durable reopen and portable restore require a current trusted environment that matches the saved strict policy. [Configure executor tools and network policy](https://github.com/openai/openai-agents-js/blob/feat/codex-harness/packages/agents-codex/examples/guides/executors.md#managed-executor-network-policy).

### Select instructions and MCP tools

The native SDK uses a managed Codex home. Leave `projectGuidance` off to skip supplemental guidance from `.claude/rules` in the selected workspace. Pass trusted UTF-8 files as `instructionFiles` to add their contents to the session instructions in order.

For a local profile, give `selectMcpTools` a client your application owns. List the tools the worker needs and set an approval rule for sensitive calls. Deny unexpected native approvals with `await session.respond(request.reply('deny'))` while the request is live. Select tools carefully because some can run without an approval request. [Select MCP tools](https://github.com/openai/openai-agents-js/blob/feat/codex-harness/packages/agents-codex/examples/guides/mcp.md#materialize-a-borrowed-sdk-mcp-namespace).

## Steer a specific turn

Read the native `turnId` from the root's `turn_started` observation. Send that ID with the supervisor's revision to `turn.steerExact(input, expectedTurnId)`. The returned `SteeringReceipt` has `sessionId`, `submissionId`, `turnId`, and `inputId`. It confirms that the native runtime accepted the input for that turn.

If the root no longer owns that active native turn, `steerExact` rejects with `StaleTurnError`. Refresh the supervisor's view. Send any new instruction only after the supervisor chooses its target. Use `turn.steer(input)` when input may follow the same root's owned continuation. After completion, submit feedback as a new turn in the same session. The new turn keeps the conversation context.

## Wait for a result or a decision

`await session.submit(input)` returns the `Turn` that owns the submitted work. Use `await turn.wait()` for its completed result. Use `await turn.waitForAttention()` if the worker can need a supervisor decision.

`waitForAttention()` waits through ordinary tool activity and returns one of three outcomes.

- A completed result with `finalOutput`.
- Live `requests` from this turn that the application can answer.
- A `TurnNeedsAttention` with `type: 'needs_attention'`, the `error`, and current `rateLimits`. Known terminal reasons are `interrupted`, `connection_lost`, `rate_limited`, and `quota_blocked`.

Unclassified failures reject the wait. To handle requests from across the session, [read its pending interactions](https://github.com/openai/openai-agents-js/blob/feat/codex-harness/packages/agents-codex/examples/guides/interactions.md#read-pending-interactions).

Give session opening its own deadline with the `signal` option. Set separate deadlines for application callbacks and MCP transports. An abort signal on `waitForAttention` stops that wait. When your deadline should also stop the turn, call `turn.cancel()` and wait for cleanup before releasing the worker. Cleanup can outlast the deadline. Earlier effects may already have reached the workspace or an external service.

Use `await session.interrupt()` to return as soon as the SDK accepts a root stop. Keep the Session alive and call `await session.close()` to join cleanup before the worker exits. To stop the captured root and join its cleanup in one call, use `await turn.cancel()`.

### Read API-key rate limits

`session.rateLimits()` starts empty in each live session. It returns the latest usable snapshot from provider response headers. Each usable response replaces the previous snapshot. `api_rate_limits_updated` observations carry the new value in `snapshot`.

A snapshot can include rate-limit windows for `requests`, `tokens`, and `projectTokens`. Each window can contain `limit`, `remaining`, and `resetAfterSeconds`. Counts can be `bigint` when they exceed JavaScript's safe integer range.

The snapshot may also include `retryAfterSeconds` or `retryAt`. Treat missing fields as unknown. These fields report API-key limits and retry advice. Read token usage separately and check the operation's effects before deciding when to retry.

## Check execution and turn receipts

Read `execution_item_completed` from `turn.events()` or `session.events()` to track commands, patches, and MCP calls run by Codex. By default, each item reports its type, IDs, and status.

For a trusted supervisor that needs details, use `session.events({ includeExecutionDetails: true })` or `turn.events({ includeExecutionDetails: true })`. Command details can include the original `argv`, working directory, and exit code. Check the recorded status and exit code before accepting a command result. Details can also include patch contents and MCP arguments and results. Keep these payloads private.

The compact and detailed views share sequence numbers and IDs. Match the observed item to its full retained entry in `session.items()` using the thread, turn, item, and call IDs. If a `gap` reports missing observations, consult that history. History and live events can have different retention limits. Calls through `selectMcpTools` appear as function calls and outputs in `session.items()`.

Each record from `session.turns()` can include a `receipt` for its latest recorded model sampling attempt. The receipt gives the model and reasoning setting. It identifies the Codex build by revision and source tree. It records the developer instruction hash, loaded instruction file hashes, user configuration flag, and approval policy. The `executors` field records the applied policy when available. A portable restore withholds executor details in that field. Check artifact bytes separately and treat missing receipts from older or unsampled turns as unknown.

## Reopen after an uncertain tool call

Reopen the conversation with `agent.session({ storage, resume: sessionId, environment })` after the old worker releases the writer. Supply your current credentials and tool declarations again. The local profile preserves conversation state. Keep artifacts and your application journal in their own durable storage.

A crash can leave a tool invocation in history without its result. If opening raises `LocalRecoveryRequired`, inspect `error.calls` for the original IDs, tool name, namespace, and argument text. Read `error.turns` and `error.items` for the records that reached the profile. An `interrupted` turn has no recorded terminal status. Keep this history and the call arguments private.

Check an independent application record, such as a service receipt or a committed transaction. Keep the worker paused if any effect is still unknown.

After confirming every requested outcome, call `agent.session()` with the same opening options and `reconciledCalls`. For each `ReconciledCall`, copy `threadId`, `turnId`, and `callId` from the inspected call. Set `outcome` to `applied` or `not_applied` and put model-visible text in `result`.

The SDK records the verified results before admitting the session and blocks reuse of those call IDs. Reopening with an identical receipt succeeds. A conflicting result fails. Use a stable application operation key to prevent duplicates under new call IDs.

Recovery applies to supported root calls that are still in model context. An unfinished descendant can block cold reopen.

## Run the reference worker

The example runs two conversations in separate worker processes and workspaces. It reopens them after the processes exit and sends feedback to the original conversation. It checks a structured result against the saved artifact and command evidence. The result can include a question for review. A separate application step records an accepted artifact under a stable key. The worker applies one turn deadline to submission and the wait for attention.

Its snapshot measures opening, follow-up submission and completion separately. It distinguishes the first managed tool start (`firstToolMs`) from the first observed tool result (`firstToolResultMs`).

Run the example on Linux to exercise supervision and recovery with scripted responses. Your application owns the worker processes, the journal, artifact review, publication, and production measurements. [Run the supervised worker example](https://github.com/openai/openai-agents-js/blob/feat/codex-harness/packages/agents-codex/examples/supervised-worker/README.md).
