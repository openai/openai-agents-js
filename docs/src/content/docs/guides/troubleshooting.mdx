## Supported environments

The OpenAI Agents SDK supports these server environments:

- Node.js 22+
- Deno 2.35+
- Bun 1.2.5+

### Limited support

#### Cloudflare Workers

- Enable `nodejs_compat`.
- Flush traces at the end of the request. [See the tracing guide](/openai-agents-js/guides/tracing#export-loop-lifecycle) for details.
- Cloudflare Workers' limited support for `AsyncLocalStorage` can make some traces inaccurate.
- For Realtime voice, use [`CloudflareRealtimeTransportLayer`](/openai-agents-js/extensions/cloudflare) from `@openai/agents-extensions`. The adapter opens a WebSocket with a `fetch()` upgrade.

#### Responses API WebSocket transport

- Requires a global `WebSocket` implementation.
- The `WebSocket` implementation must support custom headers for the handshake.
- Many browser-style WebSocket APIs (and some edge runtimes) do not support custom outbound headers. In those environments, use the default HTTP Responses transport instead.
- If you see errors mentioning a missing global `WebSocket` implementation or lack of custom-header support, the runtime websocket implementation is not compatible with the Responses WebSocket transport.

#### Browsers

The core SDK can be bundled for browser use, but tracing is disabled by default there.

#### React Native

- `@openai/agents-core` and `@openai/agents-realtime` provide React Native package conditions for portable shims, but the built-in `OpenAIRealtimeWebRTC` remains browser-only.
- Realtime apps must provide an app-owned transport backed by a native WebRTC implementation such as `react-native-webrtc`, and the app remains responsible for permissions, audio routing, and transport lifecycle.
- Expo Go cannot load native WebRTC modules. Use an Expo development build or a native React Native project. See the [`examples/realtime-react-native`](https://github.com/openai/openai-agents-js/tree/feat/codex-harness/examples/realtime-react-native) example.

#### v8 isolates

- You should be able to bundle the SDK for v8 isolates with a bundler that supplies the right browser polyfills, but tracing will not work.
- v8 isolates have not been extensively tested.

## Debug logging

To investigate SDK problems, enable debug logging. Set the `DEBUG` environment variable to `openai-agents:*`.

```bash
export DEBUG=openai-agents:*
```

Model and tool data remains redacted by default. If you need those details, see [Sensitive data in logs](/openai-agents-js/guides/config#sensitive-data-in-logs) and only opt in where logs are handled securely.

To log only one part of the SDK, use one of these values:

- `openai-agents:core` for the main execution logic of the SDK
- `openai-agents:openai` for OpenAI API calls
- `openai-agents:realtime` for Voice Agents components
