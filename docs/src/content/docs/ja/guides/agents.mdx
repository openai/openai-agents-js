エージェントは、OpenAI Agents SDK の主要な構成要素です。 **エージェント** は、次の設定を持つ大規模言語モデル（LLM）です。

- **指示** – モデルに _自身の役割_ と _応答方法_ を伝えるシステムプロンプトです。
- **モデル** – 呼び出す OpenAI モデルと、任意のモデル調整パラメーターです。
- **ツール** – LLM がタスクを遂行するために呼び出せる関数や API のリストです。

## エージェントの基本

### 基本設定

`Agent` コンストラクターは、単一の設定オブジェクトを受け取ります。よく使用されるプロパティを以下に示します。

| プロパティ | 必須 | 説明 |
| --- | --- | --- |
| `name` | はい | 人間が読みやすい短い識別子です。 |
| `instructions` | はい | システムプロンプトです（文字列 **または** 関数。[動的な指示](#dynamic-instructions)を参照）。 |
| `prompt` | いいえ | OpenAI Responses API のプロンプト設定です。静的なプロンプトオブジェクトまたは関数を受け取ります。[プロンプト](/openai-agents-js/ja/guides/models#prompt)を参照してください。 |
| `handoffDescription` | いいえ | このエージェントをハンドオフツールとして提供する際に使用される短い説明です。 |
| `handoffs` | いいえ | 専門エージェントに会話を委譲します。[構成パターン](#composition-patterns)と[ハンドオフ](/openai-agents-js/ja/guides/handoffs)を参照してください。 |
| `model` | いいえ | モデル名 **または** カスタムの [`Model`](/openai-agents-js/openai/agents/interfaces/model/) 実装です。 |
| `modelSettings` | いいえ | 調整パラメーター（temperature、top_p など）です。[モデル](/openai-agents-js/ja/guides/models#modelsettings)を参照してください。必要なプロパティがトップレベルにない場合は、`providerData` 内に含めることができます。 |
| `tools` | いいえ | モデルが呼び出せる [`Tool`](/openai-agents-js/openai/agents/type-aliases/tool/) インスタンスの配列です。[ツール](/openai-agents-js/ja/guides/tools)を参照してください。 |
| `mcpServers` | いいえ | エージェントにツールを提供する MCP サーバーです。[MCP 連携](/openai-agents-js/ja/guides/mcp)を参照してください。 |
| `mcpConfig` | いいえ | 厳密なスキーマ、エラー処理、サーバー名をプレフィックスに付けたツール名など、ローカル MCP ツールのオプションです。[エージェントレベルの MCP 設定](/openai-agents-js/ja/guides/mcp#agent-level-mcp-configuration)を参照してください。 |
| `inputGuardrails` | いいえ | このエージェントチェーンの最初のユーザー入力に適用されるガードレールです。[ガードレール](/openai-agents-js/ja/guides/guardrails)を参照してください。 |
| `outputGuardrails` | いいえ | このエージェントの最終出力に適用されるガードレールです。[ガードレール](/openai-agents-js/ja/guides/guardrails)を参照してください。 |
| `outputType` | いいえ | プレーンテキストの代わりに構造化された出力を返します。[出力型](#output-types)と[エージェントの実行結果](/openai-agents-js/ja/guides/results#final-output)を参照してください。 |
| `toolUseBehavior` | いいえ | SDK が関数ツールの結果をモデルに返すか、関数ツールの結果を実行の最終出力として使用するかを制御します。[ツール使用の強制](#forcing-tool-use)を参照してください。 |
| `resetToolChoice` | いいえ | ツール呼び出し後に `toolChoice` をデフォルト値にリセットし（デフォルト: `true`）、ツール使用のループを防ぎます。[ツール使用の強制](#forcing-tool-use)を参照してください。 |
| `handoffOutputTypeWarningEnabled` | いいえ | ハンドオフ先の出力型が異なる場合に警告を出します（デフォルト: `true`）。[エージェントの実行結果](/openai-agents-js/ja/guides/results#final-output)を参照してください。 |

### 出力型

デフォルトでは、エージェントは **プレーンテキスト** （`string`）を返します。モデルから構造化されたオブジェクトを返したい場合は、`outputType` プロパティを指定できます。SDK は次の形式を受け付けます。

1. [Zod](https://github.com/colinhacks/zod) スキーマ（`z.object({...})`）。
2. Standard JSON Schema への変換に対応した、サポート対象の Standard Schema 値。
3. 任意の JSON Schema 互換オブジェクト。

<Code
  lang="typescript"
  code={agentWithZodOutputType}
  title="Zod による構造化された出力"
/>

`outputType` を指定すると、SDK はプレーンテキストの代わりに [structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs) を自動的に使用します。

Zod とサポート対象の Standard Schema 値は、パースされた出力をローカルで検証し、推論された出力型を保持します。元の JSON Schema はモデルが従う仕様を記述しますが、パース結果は `unknown` のままです。Standard Schema の例とサポートされる検証範囲については、[スキーマ検証](/openai-agents-js/ja/guides/schemas)を参照してください。

### OpenAI プラットフォームとの対応関係

エージェントの概念の中には、OpenAI プラットフォームの概念に直接対応するものもあれば、エージェントの定義時ではなく実行時に設定するものもあります。

| SDK の概念 | OpenAI のガイド | 関連する場面 |
| --- | --- | --- |
| `outputType` | [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) | エージェントからテキストではなく、型付きの JSON やスキーマ検証済みのオブジェクトを返したい場合。 |
| `tools` / 組み込みツール（Hosted） | [ツールガイド](https://developers.openai.com/api/docs/guides/tools) | モデルに検索、情報取得、コード実行、独自の関数やツールの呼び出しを行わせたい場合。 |
| `conversationId` / `previousResponseId` | [会話の状態](https://developers.openai.com/api/docs/guides/conversation-state) | OpenAI に会話の状態を永続化させたり、ターン間でつなげたりしたい場合。 |

`conversationId` と `previousResponseId` は実行時の制御項目であり、`Agent` コンストラクターのフィールドではありません。これらの SDK エントリーポイントが必要な場合は、[エージェントの実行](/openai-agents-js/ja/guides/running-agents)を参照してください。

## 構成パターン

エージェントがより大きなワークフローに参加する際によく使われる SDK のエントリーポイントは、次の 2 つです。

1. **マネージャー（agents as tools）** – 中央のエージェントが会話を管理し、ツールとして公開された専門エージェントを呼び出します。
2. **ハンドオフ** – 最初のエージェントがユーザーのリクエストを特定すると、会話全体を専門エージェントに委譲します。

これらのアプローチは相互補完的です。マネージャーでは、ガードレールやレート制限を一か所で適用できます。一方、ハンドオフでは、会話の制御を保持し続けることなく、各エージェントが単一のタスクに集中できます。設計上のトレードオフと各パターンを選ぶタイミングについては、[エージェントオーケストレーション](/openai-agents-js/ja/guides/multi-agent)を参照してください。

#### マネージャー（agents as tools）

このパターンでは、マネージャーが制御を渡すことはありません。LLM がツールを使用し、マネージャーが最終的な回答をまとめます。詳しくは、[ツール](/openai-agents-js/ja/guides/tools#4-agents-as-tools)を参照してください。

### ライフサイクルフック

高度なユースケースでは、イベントをリッスンすることでエージェントのライフサイクルを監視できます。

`Agent` インスタンスは、そのエージェントインスタンス固有のライフサイクルイベントを発行します。一方、`Runner` は同じイベント名のイベントを、実行全体にわたる単一のストリームとして発行します。これは、ハンドオフやツール呼び出しを一か所で監視したいマルチエージェントワークフローで便利です。

共通のイベント名は次のとおりです。

| イベント | Agent フックの引数 | Runner フックの引数 |
| --- | --- | --- |
| `agent_start` | `(context, agent, turnInput?)` | `(context, agent, turnInput?)` |
| `agent_end` | `(context, output)` | `(context, agent, output)` |
| `agent_handoff` | `(context, nextAgent)` | `(context, fromAgent, toAgent)` |
| `agent_tool_start` | `(context, tool, { toolCall })` | `(context, agent, tool, { toolCall })` |
| `agent_tool_end` | `(context, tool, result, { toolCall })` | `(context, agent, tool, result, { toolCall })` |

### エージェントのクローン / コピー

既存のエージェントを少し変更したバージョンが必要な場合は、まったく新しい `Agent` インスタンスを返す `clone()` メソッドを使用してください。

<Code lang="typescript" code={agentCloning} title="エージェントのクローン" />

`clone()` は、`tools`、`handoffs`、`mcpServers`、`inputGuardrails`、`outputGuardrails` などのリスト型プロパティをコピーしません。クローンの設定でこれらのプロパティを省略すると、元のエージェントとクローンは同じ配列を共有するため、どちらかのエージェントを通じて配列を変更すると、両方のエージェントに影響します。クローンに独自の配列を持たせるには、`tools: [...agent.tools, extraTool]` のように新しい配列を渡してください。ただし、新しい配列内の要素は、引き続き同じツールやハンドオフのオブジェクトです。リスト型プロパティに `undefined` を渡した場合は、そのプロパティを指定したものと見なされ、元の配列を継承せず、空のリストとして初期化されます。

### ツール使用の強制

ツールを提供しても、LLM が必ず呼び出すとは限りません。`modelSettings.toolChoice` を使用すると、ツールの使用を **強制** できます。

1. `'auto'`（デフォルト）– LLM がツールを使用するかどうかを判断します。
2. `'required'` – LLM は _必ず_ ツールを呼び出します（どのツールを呼び出すかは選択できます）。
3. `'none'` – LLM はツールを **呼び出してはいけません** 。
4. `'calculator'` などの特定のツール名 – LLM は指定されたツールを必ず呼び出します。

OpenAI Responses で利用可能なツールが `computerTool()` の場合、`toolChoice: 'computer'` は特別な意味を持ちます。`'computer'` を単なる関数名として扱うのではなく、一般提供（GA）の組み込みコンピュータツールの使用を強制します。SDK は、古い連携向けにプレビュー版と互換性のあるコンピュータツールのセレクターも受け付けますが、新しいコードでは `'computer'` を優先してください。コンピュータツールが利用できない場合、この文字列はほかの関数ツール名と同様に動作します。

<Code lang="typescript" code={agentForcingToolUse} title="ツール使用の強制" />

`toolNamespace()`、`deferLoading: true` を指定した関数ツール、`deferLoading: true` を指定したリモート MCP ツールなど、遅延読み込みされる Responses ツールを使用する場合は、`modelSettings.toolChoice` を `'auto'` のままにしてください。モデルがそれらの定義を読み込むタイミングを判断する必要があるため、SDK は、遅延読み込みされるツールや組み込みの `tool_search` ヘルパーを名前で指定して強制することを拒否します。ツール検索の設定全体については、[ツール](/openai-agents-js/ja/guides/tools#deferred-tool-loading-with-tool-search)を参照してください。

#### 無限ループの防止

ツール呼び出し後、SDK は `toolChoice` を自動的に `'auto'` にリセットします。これにより、モデルがツールを繰り返し呼び出そうとする無限ループに陥るのを防ぎます。この動作は、`resetToolChoice` フラグ、または `toolUseBehavior` の設定で変更できます。

- `'run_llm_again'`（デフォルト）– ツールの結果を使って LLM を再実行します。
- `'stop_on_first_tool'` – 最初のツールの結果を最終的な回答として扱います。
- `{ stopAtToolNames: ['my_tool'] }` – リスト内のいずれかのツールが呼び出されたら停止します。
- `(context, toolResults) => ...` – 実行を終了すべきかどうかを返すカスタム関数です。
