コンテキストは多義的に使われる用語です。主に考慮すべきコンテキストには、次の 2 種類があります。

1. **ローカルコンテキスト** は、実行中にコードからアクセスできるコンテキストです。これには、ツールが必要とする依存関係やデータ、`onHandoff` などのコールバック、ライフサイクルフックが含まれます。
2. **LLM から見えるコンテキスト** は、言語モデルが回答を生成するときに参照できるコンテキストです。

## ローカルコンテキスト

ローカルコンテキストは、`RunContext<T>` 型で表されます。状態や依存関係を保持する任意のオブジェクトを作成し、それを `Runner.run()` に渡します。すべてのツール呼び出しとフックは `RunContext` ラッパーを受け取るため、そのオブジェクトを読み取ったり変更したりできます。

ローカルコンテキストは、次のような用途に使用します。

- 実行に関するデータ（ユーザー名、ID など）
- ロガーやデータ取得機能などの依存関係
- ヘルパー関数

<Aside type="note">
  コンテキストオブジェクトは LLM に **送信されません**
  。これは完全にローカルなものであり、 自由に読み書きできます。
</Aside>

### `RunContext` の公開情報

`RunContext<T>` は、アプリで定義したコンテキストオブジェクトのラッパーです。実際には、主に次の項目を使用します。

- `runContext.context`：アプリ独自の変更可能な状態と依存関係
- `runContext.usage`：現在の実行で集計されたトークンおよびリクエストの使用量
- `runContext.toolInput`：現在の実行が `agent.asTool()` 内で行われている場合の構造化入力
- `runContext.approveTool(...)` / `runContext.rejectTool(...)`：承認状態をプログラムから更新する場合

アプリで定義したオブジェクトは `runContext.context` のみです。その他のフィールドは、SDK が管理する実行時メタデータです。

後で [人間の介入（HITL）](/openai-agents-js/ja/guides/human-in-the-loop) のために [`RunState`](/openai-agents-js/ja/guides/results#interruptions-and-resumable-state) をシリアライズする場合、この実行時メタデータも状態とともに保存されます。シリアライズした状態を永続化または送信する予定がある場合は、`runContext.context` に機密情報を含めないでください。

<Aside type="note">
  `RunContext` は、現在の実行におけるローカルなアプリ状態を扱います。会話状態は
  別の関心事です。会話ターンをどのように引き継ぐかに応じて、`result.history`、`session`、
  `conversationId`、または `previousResponseId`
  を使用します。この使い分けについては、
  [エージェントの実行](/openai-agents-js/ja/guides/running-agents#state-and-conversation-management)
  を参照してください。
</Aside>

`RunContext` をサブクラス化する場合は、ネストされた実行や派生した実行でも、依存しているサブクラス固有のインスタンス状態が保持されることを確認してください。SDK は、ネストされた実行中に内部で分岐したコンテキストを作成します。

## LLM から見えるコンテキスト

LLM が呼び出されたとき、LLM が参照できるデータは会話履歴に含まれるものだけです。追加情報を利用できるようにするには、次の選択肢があります。

1. エージェントの `instructions` に追加します。これは、システムメッセージまたは開発者メッセージとも呼ばれます。静的な文字列のほか、コンテキストを受け取って文字列を返す関数も使用できます。
2. `Runner.run()` を呼び出すときに `input` に含めます。これは `instructions` を使う方法と似ていますが、メッセージを[指揮系統](https://cdn.openai.com/spec/model-spec-2024-05-08.html#follow-the-chain-of-command)のより下位に配置できます。
3. 関数ツールを通じて追加情報を公開し、LLM が必要に応じてその情報を取得できるようにします。
4. 情報取得ツールまたは Web 検索ツールを使用し、ファイル、データベース、Web の関連データに基づいて回答を生成します。
