「コンテキスト」という用語は、複数の意味で使われます。ここで関係するコンテキストは、大きく 2 種類に分けられます。

1. **ローカルコンテキスト** は、実行中にコードからアクセスできるものです。ツール、`onHandoff` などのコールバック、ライフサイクルフックが必要とする依存関係やデータを含みます。
2. **LLM から見えるコンテキスト** は、応答を生成する際に言語モデルが参照できるものです。

## ローカルコンテキスト

ローカルコンテキストは、`RunContext<T>` 型で表されます。状態や依存関係を保持する任意のオブジェクトを作成し、`Runner.run()` に渡します。すべてのツール呼び出しとフックは `RunContext` ラッパーを受け取り、そのオブジェクトを読み取ったり変更したりできます。

単一の実行に参加するすべてのエージェント、ツール、フックは、同じ **型** のコンテキストを使用する必要があります。

ローカルコンテキストは、次のような用途に使用します。

- 実行に関するデータ（ユーザー名、ID など）
- ロガーやデータ取得処理などの依存関係
- ヘルパー関数

<Aside type="note">
  コンテキストオブジェクトは LLM に **送信されません**
  。これは完全にローカルなものであり、 自由に読み書きできます。
</Aside>

単一の実行内では、派生コンテキストは基盤となる同じアプリケーションコンテキスト、承認情報、使用量の追跡情報を共有します。ネストされた `agent.asTool()` の実行には、異なる `toolInput` が付与される場合がありますが、デフォルトではアプリケーションの状態の独立したコピーは作成されません。

### ローカルコンテキストによる機能の可視性の制御

関数ツール、ローカル MCP ツール、ハンドオフが同じリクエストポリシーに依存する場合は、ポリシーの入力値やヘルパーをアプリケーションコンテキストに保持してください。SDK の各インターフェースは、それぞれのコールバックを通じて現在の実行コンテキストを公開します。

- `tool()` で作成した関数ツールの `isEnabled` 述語は、`runContext` プロパティに現在の `RunContext` を持つオブジェクトを受け取ります。
- ハンドオフの `isEnabled` 述語は、`runContext` プロパティに現在の `RunContext` を持つオブジェクトを受け取ります。
- 呼び出し可能な MCP [`toolFilter`](/openai-agents-js/ja/guides/mcp#tool-filtering) は、`runContext` プロパティに現在の `RunContext` を持つ `MCPToolFilterContext` を受け取ります。

機能のリストを個別に管理するのではなく、共通のアプリケーションポリシーをこれらのコールバックに適用してください。コールバックは、SDK が現在のターンでどの機能をモデルに公開するかを制御します。モデルがツールやハンドオフの引数を生成する前に実行されるため、モデルが生成した引数やリソースの選択を認可することはできません。関数ツールでは、そのような認可判断を `execute` 内で適用するか、必要に応じて [ツール入力のガードレール](/openai-agents-js/ja/guides/guardrails#tool-guardrails) と [人間の介入（HITL）](/openai-agents-js/ja/guides/human-in-the-loop) による承認を追加してください。MCP サーバーは、保護対象の操作について自ら認可を行う必要があります。`inputType` を持つハンドオフでは、`onHandoff` の冒頭で、アプリケーションの副作用が発生する前にパース済みの入力を確認し、認可に失敗した場合は例外をスローしてください。`onHandoff` が正常に終了すると引き継ぎが続行されます。また、ツール入力のガードレールはハンドオフでは実行されません。コールバックのライフサイクルについては、[ハンドオフの入力](/openai-agents-js/ja/guides/handoffs#handoff-inputs) を参照してください。

呼び出し可能な MCP `toolFilter` がリクエストコンテキストに依存する場合は、エージェントが管理するサーバーの `cacheToolsList` を無効のままにしてください。キャッシュエントリにはフィルタリング済みのツールリストが含まれますが、呼び出し可能なフィルターのデフォルトのキャッシュキーは、リクエストコンテキストごとに区別されません。`getAllMcpTools(...)` を直接呼び出すコードでは、代わりに、関連するポリシーの識別情報を含む `generateMCPToolCacheKey` を指定できます。[MCP のキャッシュに関するガイダンス](/openai-agents-js/ja/guides/mcp#other-things-to-know) を参照してください。

### `RunContext` が公開する情報

`RunContext<T>` は、アプリケーションで定義したコンテキストオブジェクトのラッパーです。実際には、主に次のものを使用します。

- `runContext.context` は、独自の変更可能なアプリケーションの状態や依存関係に使用します。
- `runContext.usage` は、現在の実行で集計されたトークンやリクエストの使用量に使用します。
- `runContext.toolInput` は、現在の実行が `agent.asTool()` 内で行われている場合の構造化された入力に使用します。
- `runContext.approveTool(...)` / `runContext.rejectTool(...)` は、承認状態をプログラムから更新する必要がある場合に使用します。

アプリケーションで定義したオブジェクトは `runContext.context` だけです。その他のフィールドは、SDK が管理するランタイムメタデータです。

後で [人間の介入（HITL）](/openai-agents-js/ja/guides/human-in-the-loop) のために [`RunState`](/openai-agents-js/ja/guides/results#interruptions-and-resumable-state) をシリアライズすると、そのランタイムメタデータも状態とともに保存されます。シリアライズした状態を永続化または送信する予定がある場合は、`runContext.context` に機密情報を入れないでください。

<Aside type="note">
  `RunContext`
  は、現在の実行におけるローカルなアプリケーションの状態を扱います。
  会話の状態は別の関心事です。ターンをどのように引き継ぐかに応じて、
  `result.history`、`session`、`conversationId`、または `previousResponseId`
  を使用してください。この選択については、
  [エージェントの実行](/openai-agents-js/ja/guides/running-agents#state-and-conversation-management)
  を参照してください。
</Aside>

`RunContext` をサブクラス化する場合は、ネストされた実行や派生した実行でも、利用しているサブクラス固有のインスタンス状態が保持されることを確認してください。SDK は、ネストされた実行中に内部でコンテキストを分岐させます。

## LLM から見えるコンテキスト

LLM が呼び出されるとき、参照できるデータは会話履歴に含まれるものだけです。追加の情報を利用できるようにするには、いくつかの方法があります。

1. エージェントの `instructions`（システムメッセージまたは開発者メッセージとも呼ばれます）に追加します。これは固定の文字列でも、コンテキストを受け取って文字列を返す関数でもかまいません。
2. `Runner.run()` を呼び出すときに `input` に含めます。これは instructions を使う方法に似ていますが、[指示の優先順位](https://cdn.openai.com/spec/model-spec-2024-05-08.html#follow-the-chain-of-command) でメッセージをより低い位置に置くことができます。
3. 関数ツールを通じて追加情報を公開し、LLM が必要に応じてその情報を取得できるようにします。
4. 検索ツールや Web 検索ツールを使用し、ファイル、データベース、Web にある関連データに基づいた応答を生成します。
