## 概要

![音声エージェント](https://cdn.openai.com/API/docs/images/diagram-speech-to-speech.png)

音声エージェントを使うと、OpenAI の音声対音声モデルを基盤とする低遅延の音声インターフェースを構築できます。SDK は Realtime API のメンタルモデルをそのまま維持しつつ、元のイベントフローを `RealtimeAgent`、`RealtimeSession`、トランスポートヘルパーでラップすることで、ツール、ガードレール、ハンドオフ、セッション履歴を扱いやすくします。

内部では、公式の [WebRTC を使用した Realtime API](https://developers.openai.com/api/docs/guides/realtime-webrtc/)、[リアルタイム会話](https://developers.openai.com/api/docs/guides/realtime-conversations/)、[音声アクティビティ検出](https://developers.openai.com/api/docs/guides/realtime-vad/)の各ガイドで説明されている Realtime の概念がそのまま適用されます。Agents SDK は、この API の上に TypeScript ファーストのレイヤーを追加します。これにより、トランスポートやイベント処理を一から作り直すことなく、プロダクトのロジックに集中できます。

<Aside type="note">
  ブラウザークライアントを WebRTC
  で接続する場合は、クイックスタートから始めてください。
  WebRTC、WebSocket、SIP、Twilio、Cloudflare Workers
  のどれを使うか検討している場合は、
  まずリアルタイムトランスポートのガイドに進んでください。
</Aside>

## SDK が追加する機能

- 一時的なクライアントトークンを使用した、ブラウザーを主眼とする WebRTC のセットアップ
- サーバー側の WebSocket および SIP トランスポートの選択肢
- 自動的な割り込み処理とローカルの会話履歴の更新
- リアルタイムのハンドオフによるマルチエージェントのオーケストレーション
- 関数ツール、ホスト型 MCP ツール、承認、委譲パターン
- リアルタイムの音声対話における出力ガードレールとトレーシングのサポート

## 音声対音声モデルを選ぶ理由

音声対音声モデルはユーザーの音声を直接処理するため、ターンごとに音声認識、テキストによる推論、音声合成をつなぐ個別の処理チェーンを構築する必要がありません。これにより、遅延が抑えられ、リアルタイムアプリケーションでの割り込み、テキストと音声を組み合わせた入力、ツール呼び出しがより自然になります。
