最新のエージェントは、ファイルシステム上の実際のファイルを操作できるときに、その能力を最大限に発揮します。Agents SDK の **サンドボックスエージェント** は、モデルに永続的なワークスペースを提供します。ここでは、大量のドキュメントの検索、ファイルの編集、コマンドの実行、成果物の生成、保存したサンドボックスの状態からの作業再開が可能です。

SDK はこの実行基盤を提供するため、ファイルの配置、ファイルシステムツール、シェルアクセス、サンドボックスのライフサイクル、スナップショット、プロバイダー固有の連携処理を自分で組み合わせる必要はありません。通常の `Agent` と `Runner` のフローを維持したまま、ワークスペース用の `Manifest`、サンドボックスネイティブのツールを利用するための機能、作業の実行場所を指定する `sandbox` 実行オプションを追加します。

## 前提条件

- Node.js 22 以降
- OpenAI Agents SDK の基本的な知識
- サンドボックスクライアント。macOS または Linux で信頼できるローカル開発を行う場合は、`UnixLocalSandboxClient` から始めてください。Windows では、代わりに `DockerSandboxClient` またはホスト型サンドボックスクライアントを使用してください。

このクイックスタートでは Node.js と npm のコマンドを使用しますが、SDK は Node.js に限定されません。プロジェクトで互換性のあるパッケージ解決とランタイム API を使用していれば、サンドボックスエージェントは Deno や Bun でも実行できます。

## インストール

SDK をまだインストールしていない場合は、次のコマンドを実行してください。

```bash
npm install @openai/agents
```

Docker ベースのサンドボックスでは、Docker をローカルにインストールし、`@openai/agents/sandbox/local` の `DockerSandboxClient` を使用してください。

`tty: true` でローカルの対話型 PTY セッションを使用する場合、SDK を実行するプロセスからも、`python3` または `OPENAI_AGENTS_PYTHON` 経由で Python 3 を利用できる必要があります。PTY を使用しないシェルコマンドには Python は不要です。

## ローカルサンドボックスエージェントの作成

この例では、ローカルリポジトリを `repo/` 配下に配置し、ローカルスキルを遅延読み込みし、ランナーに実行用の Unix ローカルサンドボックスセッションを作成させます。エージェント定義がマニフェストと機能を保持し、実行設定では今回の実行で使用するサンドボックスクライアントだけを選択します。

`UnixLocalSandboxClient` は、macOS と Linux のどちらでも、コマンドをホストプロセスとして実行します。このクライアントは、OS レベルのファイルシステムやネットワークの分離を追加しません。この例は、信頼できるローカル開発、または外部で分離された環境内で使用してください。信頼できない入力の影響を受けるコマンドを含め、信頼できないコマンドを実行する場合は、適切に設定された Docker またはホスト型のバックエンドを選択するか、外部で分離を行ってください。Unix ローカル実行の制限については、[サンドボックスクライアント](/openai-agents-js/ja/guides/sandbox-agents/clients#local-clients)を参照してください。

## 主な選択肢

基本的な実行が動作したら、次によく検討されるのは以下の選択肢です。

- `defaultManifest`: 新規サンドボックスセッション用のファイル、リポジトリ、ディレクトリ、マウント
- `instructions`: プロンプトをまたいで適用する、簡潔なワークフロールール
- `baseInstructions`: SDK のサンドボックス用プロンプトを置き換えるための上級者向けの手段
- `capabilities`: ファイルシステムの編集や画像の確認、シェル、スキル、メモリ、コンパクションなど、サンドボックスネイティブのツール
- `runAs`: モデルに公開するツールで使用する、サンドボックス内のユーザー ID
- `sandbox.client`: サンドボックスのバックエンド
- `sandbox.session`、`sandbox.sessionState`、または `sandbox.snapshot`: 後続の実行で以前の作業に再接続する方法
