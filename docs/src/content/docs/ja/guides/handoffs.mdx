ハンドオフを使用すると、エージェントは会話の一部を別のエージェントに委任できます。これは、複数のエージェントがそれぞれ特定の分野に特化している場合に便利です。たとえば、カスタマーサポートアプリでは、予約、返金、よくある質問をそれぞれ担当するエージェントを用意できます。

ハンドオフは、LLM に対してツールとして表現されます。`Refund Agent` というエージェントにハンドオフする場合、ツール名は `transfer_to_refund_agent` になります。

> スペシャリストが会話を引き継ぐ必要があると判断したら、[エージェント](/openai-agents-js/ja/guides/agents#composition-patterns)の次にこのページをお読みください。スペシャリストを元のエージェントの背後で動作させる場合は、代わりに [agents as tools](/openai-agents-js/ja/guides/tools#4-agents-as-tools)を使用してください。

## ハンドオフの作成

すべてのエージェントは `handoffs` オプションを受け取ります。このオプションには、他の `Agent` インスタンス、または `handoff()` ヘルパーが返す `Handoff` オブジェクトを含めることができます。

通常の `Agent` インスタンスを渡すと、その `handoffDescription` が指定されている場合、デフォルトのツール説明に追加されます。モデルがそのハンドオフを選択すべきタイミングを明確にするために使用してください。

### `handoff()` によるハンドオフのカスタマイズ

`handoff()` 関数を使用すると、生成されるツールを調整できます。

- `agent` – ハンドオフ先のエージェント
- `toolNameOverride` – デフォルトの `transfer_to_<agent_name>` ツール名の上書き
- `toolDescriptionOverride` – デフォルトのツール説明の上書き
- `onHandoff` – ハンドオフ発生時のコールバック。`RunContext` と、`inputType` が設定されている場合は解析済みのハンドオフペイロードを受け取ります
- `inputType` – ハンドオフのツール呼び出し引数に使用するスキーマ
- `inputFilter` – 次のエージェントに渡される履歴のフィルター
- `isEnabled` – 条件に一致する実行に対してのみハンドオフを公開する真偽値または述語

`handoff()` ヘルパーは、渡された特定の `agent` に常に制御を移します。移行先が複数ある場合は、移行先ごとに 1 つのハンドオフを登録し、モデルに選択させます。独自のハンドオフコードが呼び出し時に返すエージェントを決定する必要がある場合は、カスタム `Handoff` を使用してください。

## ハンドオフ入力

モデルがハンドオフを選択する際に、小さな構造化ペイロードを付加させたい場合があります。その場合は、`inputType` と `onHandoff` を一緒に定義します。

<Code lang="typescript" code={handoffInputExample} title="ハンドオフ入力" />

`inputType` は、ハンドオフのツール呼び出し自体の引数を記述します。SDK はそのスキーマをハンドオフツールの `parameters` としてモデルに公開し、返された引数をローカルで解析して、その解析済みの値を `onHandoff` に渡します。

これは次のエージェントのメイン入力を置き換えるものではなく、別の移行先を選択するものでもありません。`handoff()` ヘルパーは引き続きラップした特定のエージェントに移行し、受け取るエージェントには、`inputFilter` で変更しない限り、会話履歴が渡されます。

また、`inputType` は `RunContext` とは別のものです。ローカルにすでに存在するアプリケーションの状態や依存関係ではなく、ハンドオフ時にモデルが決定するメタデータに使用してください。

### `inputType` の使用場面

ハンドオフに `reason`、`language`、`priority`、`summary` など、モデルが生成する少量のルーティングメタデータが必要な場合は、`inputType` を使用します。たとえば、トリアージエージェントは `{ reason: 'duplicate_charge', priority: 'high' }` を添えて返金エージェントにハンドオフでき、返金エージェントが引き継ぐ前に `onHandoff` でそのメタデータを記録または永続化できます。

目的が異なる場合は、別の仕組みを選択してください。

- 既存のアプリケーションの状態は `RunContext` に格納します。
- 受け取るエージェントに表示される履歴を変更する場合は、`inputFilter` を使用します。
- 複数のスペシャリストが移行先の候補となる場合は、移行先ごとに 1 つのハンドオフを登録します。`inputType` は選択されたハンドオフにメタデータを追加できますが、移行先の振り分けは行いません。
- `onHandoff` の実行前に SDK で解析済みペイロードを検証する場合は、Zod スキーマまたはサポートされている Standard Schema 値を使用することを推奨します。元の JSON Schema は、モデルに送信されるツールの規約を定義するだけです。Standard Schema の例については、[スキーマ検証](/openai-agents-js/ja/guides/schemas)を参照してください。

## 入力フィルター

デフォルトでは、ハンドオフは会話履歴全体を受け取ります。次のエージェントに渡される内容を変更するには、`inputFilter` を指定します。一般的なヘルパーは `@openai/agents-core/extensions` にあります。

<Code lang="typescript" code={inputFilterExample} title="入力フィルター" />

`inputFilter` は `HandoffInputData` オブジェクトを受け取り、返します。

- `inputHistory` – 実行開始前の入力履歴
- `preHandoffItems` – ハンドオフが発生したターンより前に生成された項目
- `newItems` – ハンドオフの呼び出し項目と出力項目を含む、現在のターン中に生成された項目
- `runContext` – アクティブな実行コンテキスト

`Runner` に `handoffInputFilter` も設定している場合、その特定のハンドオフでは、ハンドオフごとの `inputFilter` が優先されます。

<Aside type="note">
  ハンドオフは単一の実行内で完結します。入力ガードレールは引き続き
  チェーン内の最初のエージェントにのみ適用され、出力ガードレールは
  最終出力を生成するエージェントにのみ適用されます。ワークフロー内の
  各カスタム関数ツール呼び出しをチェックする必要がある場合は、ツールガードレールを使用してください。
</Aside>
