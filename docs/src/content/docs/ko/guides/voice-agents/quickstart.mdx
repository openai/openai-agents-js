## 프로젝트 설정 및 자격 증명

<Steps>

1. **프로젝트 생성**

   이 빠른 시작에서는 브라우저에서 사용할 수 있는 실시간 에이전트를 생성합니다. 새 프로젝트의 기본 구조를 만들려면 [`Next.js`](https://nextjs.org/docs/getting-started/installation) 또는 [`Vite`](https://vite.dev/guide/installation.html)로 시작할 수 있습니다.

   ```bash
   npm create vite@latest my-project -- --template vanilla-ts
   ```

2. **권장 패키지 설치**(Zod v4 필요)

   ```bash
   npm install @openai/agents zod
   ```

3. **클라이언트 임시 토큰 생성**

   이 애플리케이션은 사용자의 브라우저에서 실행되므로 Realtime API를 통해 모델에 안전하게 연결할 방법이 필요합니다. 권장 흐름은 공식 [WebRTC를 사용하는 Realtime API](https://developers.openai.com/api/docs/guides/realtime-webrtc/) 가이드를 따릅니다. 백엔드에서 수명이 짧은 클라이언트 임시 토큰을 생성한 다음 브라우저에서 해당 토큰을 사용해 WebRTC 연결을 설정합니다. 테스트 목적으로 `curl`과 일반 OpenAI API 키를 사용해 토큰을 생성할 수도 있습니다.

   ```bash
   export OPENAI_API_KEY="sk-proj-...(your own key here)"
   curl -X POST https://api.openai.com/v1/realtime/client_secrets \
      -H "Authorization: Bearer $OPENAI_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "session": {
          "type": "realtime",
          "model": "gpt-realtime-2.1"
        }
      }'
   ```

   응답에는 `ek_` 접두사로 시작하는 최상위 `value` 필드와 실제 적용되는 `session` 객체가 포함됩니다. WebRTC 연결을 설정할 때 `value`를 클라이언트 시크릿으로 사용하세요. 이 토큰은 수명이 짧으므로 필요할 때 백엔드에서 새 토큰을 발급해야 합니다. 브라우저 세션에 `authorization` 또는 사용자 지정 `headers`가 포함된 호스티드 MCP 도구가 필요한 경우, 이러한 자격 증명을 브라우저 코드에 노출하지 말고 `POST /v1/realtime/client_secrets`로 전송하는 서버 측 `session` 페이로드에 해당 호스티드 MCP 구성을 포함하세요.

</Steps>

<Aside type="note">
  운영 환경의 브라우저 흐름에서는 브라우저가 백엔드에 새 임시 토큰을 요청하고,
  백엔드는 서버 API 키를 사용해 `POST /v1/realtime/client_secrets`를 호출하며,
  브라우저는 반환된 `ek_...` 토큰을 `session.connect(...)`에 전달합니다.
</Aside>

## 실시간 에이전트 생성 및 연결

<Steps>

1. **첫 에이전트 생성**

   새 [`RealtimeAgent`](/openai-agents-js/openai/agents-realtime/classes/realtimeagent/)를 생성하는 방식은 일반 [`Agent`](/openai-agents-js/ko/guides/agents)를 생성하는 방식과 매우 유사합니다.

   ```typescript
   import { RealtimeAgent } from '@openai/agents/realtime';

   const agent = new RealtimeAgent({
     name: 'Assistant',
     instructions: 'You are a helpful assistant.',
   });
   ```

2. **세션 생성**

   일반 에이전트와 달리 실시간 에이전트는 `RealtimeSession` 내에서 지속적으로 실행되며, 이 세션은 시간에 따른 대화와 모델 연결을 처리합니다. 또한 이 세션은 오디오 처리, 인터럽션(중단 처리), 이후 구성할 전반적인 대화 수명 주기를 관리합니다.

   ```typescript
   import { RealtimeSession } from '@openai/agents/realtime';

   const session = new RealtimeSession(agent, {
     model: 'gpt-realtime-2.1',
   });
   ```

   `RealtimeSession` 생성자는 첫 번째 인수로 `agent`를 받습니다. 이 에이전트는 사용자가 가장 먼저 상호작용하는 에이전트입니다.

3. **세션 연결**

   세션에 연결하려면 앞서 생성한 클라이언트 임시 토큰을 전달해야 합니다.

   ```typescript
   await session.connect({ apiKey: 'ek_...(put your own key here)' });
   ```

   브라우저에서는 WebRTC를 사용해 Realtime API에 연결하며 마이크 입력 캡처와 오디오 재생을 자동으로 구성합니다. 이 기본 WebRTC 경로에서 SDK는 데이터 채널이 열리는 즉시 초기 세션 구성을 전송하고, `connect()`가 완료되기 전에 일치하는 `session.updated` 확인 응답을 기다립니다. 확인 응답이 도착하지 않으면 타임아웃 방식으로 대체됩니다. Node.js와 같은 서버 런타임에서 `RealtimeSession`을 실행하면 SDK는 자동으로 WebSocket을 대신 사용합니다. WebSocket 경로에서는 소켓이 열리고 초기 구성이 전송된 후 `connect()`가 완료되므로 `session.updated`가 약간 늦게 도착할 수 있습니다. 전송 방식 선택에 관한 자세한 내용은 [전송 방식](/openai-agents-js/ko/guides/voice-agents/transport) 가이드에서 확인할 수 있습니다.

</Steps>

<Aside type="note">
  이 빠른 시작에서는 브라우저 음성 에이전트를 실행하는 가장 간단한 방식을
  사용합니다. `RealtimeSession`은 브라우저에서 실행되며 내장 WebRTC 전송 방식은
  Realtime 이벤트에 데이터 채널을 사용합니다. 브라우저에서는 오디오만 전송하고
  애플리케이션 서버가 Realtime 이벤트, 도구, 비즈니스 로직을 담당하게 하려면
  [서버 측 제어를 사용하는 브라우저
  오디오](/openai-agents-js/ko/guides/voice-agents/transport#browser-audio-with-server-side-controls)를
  참조하세요. 브라우저를 더 낮은 수준에서 제어하려면 [`examples/realtime-next`의
  `/raw-client`
  예제](https://github.com/openai/openai-agents-js/tree/main/examples/realtime-next)를
  참조하세요.
</Aside>
