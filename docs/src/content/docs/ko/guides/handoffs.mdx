핸드오프를 사용하면 에이전트가 대화의 일부를 다른 에이전트에 위임할 수 있습니다. 이는 각 에이전트가 특정 분야를 전문으로 담당할 때 유용합니다. 예를 들어 고객 지원 앱에서는 예약, 환불 또는 자주 묻는 질문을 처리하는 에이전트를 둘 수 있습니다.

핸드오프는 LLM에 도구로 제공됩니다. `Refund Agent`라는 에이전트로 핸드오프하면 도구 이름은 `transfer_to_refund_agent`가 됩니다.

> [에이전트](/openai-agents-js/ko/guides/agents#composition-patterns)를 읽고 전문 에이전트가 대화를 이어받아야 한다고 판단했다면 이 페이지를 읽어보세요. 전문 에이전트가 원래 에이전트 뒤에서 작업해야 한다면 대신 [도구](/openai-agents-js/ko/guides/tools#4-agents-as-tools)에 설명된 agents as tools 방식을 사용하세요.

## 핸드오프 생성

모든 에이전트는 `handoffs` 옵션을 지원합니다. 이 옵션에는 다른 `Agent` 인스턴스나 `handoff()` 헬퍼가 반환하는 `Handoff` 객체를 포함할 수 있습니다.

일반 `Agent` 인스턴스를 전달하면 해당 인스턴스의 `handoffDescription`(제공된 경우)이 기본 도구 설명에 추가됩니다. 이를 사용해 모델이 언제 해당 핸드오프를 선택해야 하는지 명확히 설명하세요.

### `handoff()`를 통한 핸드오프 사용자 지정

`handoff()` 함수를 사용하면 생성되는 도구를 조정할 수 있습니다.

- `agent` – 핸드오프 대상 에이전트
- `toolNameOverride` – 기본 `transfer_to_<agent_name>` 도구 이름 재정의
- `toolDescriptionOverride` – 기본 도구 설명 재정의
- `onHandoff` – 핸드오프 발생 시 호출되는 콜백입니다. `RunContext`를 받으며, `inputType`이 설정된 경우 파싱된 핸드오프 페이로드도 받습니다.
- `inputType` – 핸드오프 도구 호출 인자의 스키마
- `inputFilter` – 다음 에이전트에 전달되는 기록 필터링
- `isEnabled` – 조건에 맞는 실행에서만 핸드오프를 노출하는 불리언 값 또는 조건 함수

`handoff()` 헬퍼는 항상 전달한 특정 `agent`로 제어를 넘깁니다. 가능한 대상이 여러 개라면 대상마다 핸드오프를 하나씩 등록하고 모델이 그중에서 선택하도록 하세요. 호출 시점에 자체 핸드오프 코드가 반환할 에이전트를 결정해야 한다면 사용자 지정 `Handoff`를 사용하세요.

## 핸드오프 입력

모델이 핸드오프를 선택할 때 작은 구조화된 페이로드를 첨부하도록 하고 싶을 수 있습니다. 이런 경우에는 `inputType`과 `onHandoff`를 함께 정의하세요.

<Code lang="typescript" code={handoffInputExample} title="핸드오프 입력" />

`inputType`은 핸드오프 도구 호출 자체의 인자를 정의합니다. SDK는 해당 스키마를 핸드오프 도구의 `parameters`로 모델에 제공하고, 반환된 인자를 로컬에서 파싱한 뒤 파싱된 값을 `onHandoff`에 전달합니다.

`isEnabled`는 모델이 핸드오프 인자를 반환하기 전에 SDK가 모델에 제공할 핸드오프를 준비하는 동안 평가되므로, 인자를 받는 핸드오프의 인자 내부 값에 대한 권한을 검증할 수 없습니다. 권한 검증이 파싱된 필드에 따라 달라진다면 애플리케이션에 부수 효과가 발생하기 전에 `onHandoff`의 시작 부분에서 검사하세요. 권한 검증에 실패하면 반환하는 대신 예외를 던지세요. SDK는 `onHandoff`가 성공적으로 반환된 후 제어 이전을 계속합니다. 도구 입력 가드레일은 핸드오프가 아닌 함수 도구에 적용됩니다.

`inputType`은 다음 에이전트의 기본 입력을 대체하지 않으며, 다른 대상을 선택하지도 않습니다. `handoff()` 헬퍼는 여전히 래핑한 특정 에이전트로 제어를 넘기며, `inputFilter`로 변경하지 않는 한 수신 에이전트는 대화 기록을 그대로 보게 됩니다.

`inputType`은 `RunContext`와도 별개입니다. 로컬에 이미 있는 애플리케이션 상태나 의존성이 아니라, 모델이 핸드오프 시점에 결정하는 메타데이터에 사용하세요.

### `inputType` 사용 시점

핸드오프에 `reason`, `language`, `priority`, `summary`와 같이 모델이 생성하는 소량의 라우팅 메타데이터가 필요할 때 `inputType`을 사용하세요. 예를 들어 분류 에이전트는 `{ reason: 'duplicate_charge', priority: 'high' }`와 함께 환불 에이전트로 핸드오프할 수 있으며, `onHandoff`는 환불 에이전트가 대화를 이어받기 전에 해당 메타데이터를 로그에 기록하거나 영구 저장할 수 있습니다.

목적이 다르다면 다른 방식을 선택하세요.

- 기존 애플리케이션 상태는 `RunContext`에 넣으세요.
- 수신 에이전트가 볼 기록을 변경하려면 `inputFilter`를 사용하세요.
- 가능한 전문 에이전트가 여러 개라면 대상마다 핸드오프를 하나씩 등록하세요. `inputType`은 선택된 핸드오프에 메타데이터를 추가할 수 있지만, 여러 대상 중 하나로 분기하지는 않습니다.
- `onHandoff`가 실행되기 전에 SDK가 파싱된 페이로드를 검증하도록 하려면 Zod 스키마나 지원되는 Standard Schema 값을 사용하는 것이 좋습니다. JSON Schema 원문은 모델에 전달되는 도구 규약만 정의합니다. Standard Schema 예제는 [스키마 검증](/openai-agents-js/ko/guides/schemas)을 참고하세요.

## 입력 필터

기본적으로 핸드오프는 전체 대화 기록을 받습니다. 다음 에이전트에 전달되는 내용을 수정하려면 `inputFilter`를 제공하세요. 자주 사용하는 헬퍼는 `@openai/agents-core/extensions`에 있습니다.

<Code lang="typescript" code={inputFilterExample} title="입력 필터" />

`inputFilter`는 `HandoffInputData` 객체를 받아 반환합니다.

- `inputHistory` – 실행이 시작되기 전의 입력 기록
- `preHandoffItems` – 핸드오프가 발생한 턴 이전에 생성된 항목
- `newItems` – 핸드오프 호출/출력 항목을 포함하여 현재 턴에서 생성된 항목
- `runContext` – 현재 활성 상태인 실행 컨텍스트

`Runner`에 `handoffInputFilter`도 설정한 경우, 해당 핸드오프에서는 개별 핸드오프의 `inputFilter`가 우선 적용됩니다.

<Aside type="note">
  핸드오프는 단일 실행 내에서 이루어집니다. 입력 가드레일은 여전히 체인의 첫
  번째 에이전트에만 적용되며, 출력 가드레일은 최종 출력을 생성하는 에이전트에만
  적용됩니다. 워크플로 내에서 각 사용자 지정 함수 도구 호출 전후에 검사가
  필요하면 도구 가드레일을 사용하세요.
</Aside>
