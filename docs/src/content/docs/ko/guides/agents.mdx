에이전트는 OpenAI Agents SDK의 주요 구성 요소입니다. **에이전트**는 다음 항목으로 설정된 대규모 언어 모델(LLM)입니다.

- **Instructions** – 모델에 *자신의 역할*과 *응답 방식*을 알려주는 시스템 프롬프트
- **모델** – 호출할 OpenAI 모델과 선택적 모델 조정 매개변수
- **Tools** – LLM이 작업을 수행하기 위해 호출할 수 있는 함수 또는 API 목록

## 에이전트 기본 사항

### 기본 설정

`Agent` 생성자는 설정 객체 하나를 받습니다. 가장 자주 사용하는 속성은 다음과 같습니다.

| 속성 | 필수 여부 | 설명 |
| --- | --- | --- |
| `name` | 예 | 사람이 읽기 쉬운 짧은 식별자입니다. |
| `instructions` | 예 | 시스템 프롬프트입니다(문자열 **또는** 함수 – [동적 지침](#dynamic-instructions) 참고). |
| `prompt` | 아니요 | OpenAI Responses API 프롬프트 설정입니다. 정적 프롬프트 객체 또는 함수를 받습니다. [프롬프트](/openai-agents-js/ko/guides/models#prompt)를 참고하세요. |
| `handoffDescription` | 아니요 | 이 에이전트가 핸드오프 도구로 제공될 때 사용하는 짧은 설명입니다. |
| `handoffs` | 아니요 | 전문 에이전트에 대화를 위임합니다. [구성 패턴](#composition-patterns)과 [핸드오프](/openai-agents-js/ko/guides/handoffs) 가이드를 참고하세요. |
| `model` | 아니요 | 모델 이름 **또는** 사용자 정의 [`Model`](/openai-agents-js/openai/agents/interfaces/model/) 구현입니다. |
| `modelSettings` | 아니요 | 조정 매개변수(temperature, top_p 등)입니다. [모델](/openai-agents-js/ko/guides/models#modelsettings)을 참고하세요. 필요한 속성이 최상위 수준에 없으면 `providerData` 아래에 포함할 수 있습니다. |
| `tools` | 아니요 | 모델이 호출할 수 있는 [`Tool`](/openai-agents-js/openai/agents/type-aliases/tool/) 인스턴스의 배열입니다. [도구](/openai-agents-js/ko/guides/tools)를 참고하세요. |
| `mcpServers` | 아니요 | 에이전트에 도구를 제공하는 MCP 서버입니다. [모델 컨텍스트 프로토콜 (MCP)](/openai-agents-js/ko/guides/mcp) 가이드를 참고하세요. |
| `mcpConfig` | 아니요 | 엄격한 스키마, 오류 처리, 서버 이름이 접두사로 붙은 도구 이름 등 로컬 MCP 도구를 위한 옵션입니다. [에이전트 수준 MCP 설정](/openai-agents-js/ko/guides/mcp#agent-level-mcp-configuration)을 참고하세요. |
| `inputGuardrails` | 아니요 | 이 에이전트 체인의 첫 번째 사용자 입력에 적용되는 가드레일입니다. [가드레일](/openai-agents-js/ko/guides/guardrails)을 참고하세요. |
| `outputGuardrails` | 아니요 | 이 에이전트의 최종 출력에 적용되는 가드레일입니다. [가드레일](/openai-agents-js/ko/guides/guardrails)을 참고하세요. |
| `outputType` | 아니요 | 일반 텍스트 대신 구조화된 출력을 반환합니다. [출력 타입](#output-types)과 [실행 결과](/openai-agents-js/ko/guides/results#final-output)를 참고하세요. |
| `toolUseBehavior` | 아니요 | SDK가 함수 도구의 결과를 모델에 다시 보낼지, 함수 도구의 결과를 실행의 최종 출력으로 사용할지 제어합니다. [도구 사용 강제](#forcing-tool-use)를 참고하세요. |
| `resetToolChoice` | 아니요 | 도구 사용 루프를 방지하기 위해 도구 호출 후 `toolChoice`를 기본값으로 재설정합니다(기본값: `true`). [도구 사용 강제](#forcing-tool-use)를 참고하세요. |
| `handoffOutputTypeWarningEnabled` | 아니요 | 핸드오프 출력 타입이 서로 다르면 경고를 표시합니다(기본값: `true`). [실행 결과](/openai-agents-js/ko/guides/results#final-output)를 참고하세요. |

### 출력 타입

기본적으로 에이전트는 **일반 텍스트**(`string`)를 반환합니다. 모델이 구조화된 객체를 반환하도록 하려면 `outputType` 속성을 지정할 수 있습니다. SDK는 다음을 지원합니다.

1. [Zod](https://github.com/colinhacks/zod) 스키마(`z.object({...})`)

### OpenAI 플랫폼과의 매핑

일부 에이전트 개념은 OpenAI 플랫폼의 개념에 직접 대응하며, 다른 개념은 에이전트를 정의할 때가 아니라 실행할 때 설정합니다.

| SDK 개념 | OpenAI 가이드 | 필요한 상황 |
| --- | --- | --- |
| `outputType` | [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) | 에이전트가 텍스트 대신 타입이 지정된 JSON 또는 스키마로 검증된 객체를 반환해야 하는 경우 |
| `tools` / 호스티드 툴 | [도구 가이드](https://developers.openai.com/api/docs/guides/tools) | 모델이 검색, 데이터 조회, 코드 실행 또는 사용자가 정의한 함수/도구 호출을 수행해야 하는 경우 |
| `conversationId` / `previousResponseId` | [대화 상태](https://developers.openai.com/api/docs/guides/conversation-state) | OpenAI가 턴 간에 대화 상태를 저장하거나 연결하도록 하려는 경우 |

`conversationId`와 `previousResponseId`는 런타임 제어 항목이며, `Agent` 생성자의 필드가 아닙니다. 이러한 SDK 진입점이 필요하면 [에이전트 실행](/openai-agents-js/ko/guides/running-agents)을 참고하세요.

## 구성 패턴

에이전트가 더 큰 워크플로에 참여할 때 가장 자주 사용하는 SDK 진입점은 다음 두 가지입니다.

1. **매니저(agents as tools)** – 중앙 에이전트가 대화를 관리하고, 도구로 노출된 전문 에이전트를 호출합니다.
2. **핸드오프** – 최초 에이전트가 사용자의 요청을 파악한 후 전체 대화를 전문 에이전트에 위임합니다.

이 두 접근 방식은 상호 보완적입니다. 매니저를 사용하면 가드레일이나 요청 속도 제한을 한곳에서 적용할 수 있고, 핸드오프를 사용하면 각 에이전트가 대화 제어권을 계속 유지할 필요 없이 하나의 작업에 집중할 수 있습니다. 설계상의 장단점과 각 패턴을 선택할 시점은 [에이전트 오케스트레이션](/openai-agents-js/ko/guides/multi-agent)을 참고하세요.

#### 매니저(agents as tools)

이 패턴에서는 매니저가 제어권을 넘기지 않습니다. LLM이 도구를 사용하고 매니저가 최종 답변을 요약합니다. 자세한 내용은 [도구](/openai-agents-js/ko/guides/tools#4-agents-as-tools) 가이드를 참고하세요.

### 수명 주기 훅

고급 사용 사례에서는 이벤트를 수신하여 에이전트의 수명 주기를 관찰할 수 있습니다.

`Agent` 인스턴스는 해당 에이전트 인스턴스의 수명 주기 이벤트를 발생시키며, `Runner`는 전체 실행에 걸쳐 동일한 이름의 이벤트를 하나의 스트림으로 발생시킵니다. 이는 여러 에이전트를 사용하는 워크플로에서 핸드오프와 도구 호출을 한곳에서 관찰하려는 경우에 유용합니다.

공통 이벤트 이름은 다음과 같습니다.

| 이벤트 | 에이전트 훅 인수 | Runner 훅 인수 |
| --- | --- | --- |
| `agent_start` | `(context, agent, turnInput?)` | `(context, agent, turnInput?)` |
| `agent_end` | `(context, output)` | `(context, agent, output)` |
| `agent_handoff` | `(context, nextAgent)` | `(context, fromAgent, toAgent)` |
| `agent_tool_start` | `(context, tool, { toolCall })` | `(context, agent, tool, { toolCall })` |
| `agent_tool_end` | `(context, tool, result, { toolCall })` | `(context, agent, tool, result, { toolCall })` |

### 도구 사용 강제

도구를 제공한다고 해서 LLM이 반드시 도구를 호출하는 것은 아닙니다. `modelSettings.toolChoice`를 사용하면 도구 사용을 **강제**할 수 있습니다.

1. `'auto'` (기본값) – LLM이 도구 사용 여부를 결정합니다.
2. `'required'` – LLM이 _반드시_ 도구를 호출해야 합니다(어떤 도구를 호출할지는 선택할 수 있습니다).
3. `'none'` – LLM이 도구를 호출해서는 **안 됩니다**.
4. 특정 도구 이름(예: `'calculator'`) – LLM이 해당 도구를 반드시 호출해야 합니다.

OpenAI Responses에서 사용 가능한 도구가 `computerTool()`인 경우, `toolChoice: 'computer'`는 특별하게 처리됩니다. `'computer'`를 일반 함수 이름으로 취급하는 대신 정식 출시(GA)된 내장 컴퓨터 도구의 사용을 강제합니다. SDK는 기존 연동을 위해 프리뷰 버전과 호환되는 컴퓨터 선택자도 지원하지만, 새 코드에서는 `'computer'`를 사용하는 것이 좋습니다. 사용 가능한 컴퓨터 도구가 없으면 이 문자열은 다른 함수 도구 이름과 동일하게 동작합니다.

#### 무한 루프 방지

도구 호출 후 SDK는 `toolChoice`를 자동으로 `'auto'`로 재설정합니다. 이를 통해 모델이 도구 호출을 반복적으로 시도하는 무한 루프에 빠지는 것을 방지합니다. `resetToolChoice` 플래그를 사용하거나 `toolUseBehavior`를 설정하여 이 동작을 변경할 수 있습니다.

- `'run_llm_again'` (기본값) – 도구 결과와 함께 LLM을 다시 실행합니다.
- `'stop_on_first_tool'` – 첫 번째 도구 결과를 최종 답변으로 처리합니다.
- `{ stopAtToolNames: ['my_tool'] }` – 나열된 도구 중 하나가 호출되면 중지합니다.
- `(context, toolResults) => ...` – 실행을 종료할지 여부를 반환하는 사용자 정의 함수
