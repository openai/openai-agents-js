## 개요

![음성 에이전트](https://cdn.openai.com/API/docs/images/diagram-speech-to-speech.png)

음성 에이전트를 사용하면 OpenAI 음성-음성 모델을 기반으로 지연 시간이 짧은 음성 인터페이스를 구축할 수 있습니다. SDK는 Realtime API의 개념적 모델을 그대로 유지하면서 원문 이벤트 흐름을 `RealtimeAgent`, `RealtimeSession`, 전송 헬퍼로 감싸 도구, 가드레일, 핸드오프, 세션 기록을 더 쉽게 다룰 수 있도록 합니다.

내부적으로는 공식 [WebRTC를 사용하는 Realtime API](https://developers.openai.com/api/docs/guides/realtime-webrtc/), [실시간 대화](https://developers.openai.com/api/docs/guides/realtime-conversations/), [음성 활동 감지](https://developers.openai.com/api/docs/guides/realtime-vad/) 가이드에서 설명하는 Realtime 개념이 동일하게 적용됩니다. Agents SDK는 이 API 위에 TypeScript 우선 계층을 추가하므로 전송 및 이벤트 처리를 처음부터 다시 구현하는 대신 제품 로직에 집중할 수 있습니다.

<Aside type="note">
  WebRTC로 브라우저 클라이언트를 연결하려면 빠른 시작부터 살펴보세요. WebRTC,
  WebSocket, SIP, Twilio, Cloudflare Workers 중에서 선택하려면 전송 방식
  가이드를 먼저 살펴보세요.
</Aside>

## SDK가 추가하는 기능

- 임시 클라이언트 토큰을 사용하는 브라우저 우선 WebRTC 설정
- 서버 측 WebSocket 및 SIP 전송 옵션
- 인터럽션(중단 처리) 자동 처리 및 로컬 대화 기록 업데이트
- 실시간 핸드오프를 통한 다중 에이전트 오케스트레이션
- 함수 도구, 호스티드 MCP 도구, 승인, 위임 패턴
- 실시간 음성 상호작용을 위한 출력 가드레일 및 트레이싱 지원

## 음성-음성 방식의 장점

음성-음성 모델은 사용자 오디오를 직접 처리하므로 매 대화 턴마다 음성-텍스트 변환, 텍스트 추론, 텍스트-음성 변환으로 이어지는 별도의 처리 체인을 구축할 필요가 없습니다. 따라서 지연 시간이 짧게 유지되고, 실시간 애플리케이션에서 인터럽션(중단 처리), 텍스트와 음성이 혼합된 입력, 도구 호출이 훨씬 더 자연스럽게 느껴집니다.
