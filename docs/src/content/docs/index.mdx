## Overview

The [OpenAI Agents SDK for TypeScript](https://github.com/openai/openai-agents-js) lets you build agentic AI apps with a small set of abstractions. It's a production-ready upgrade of our earlier agent experiment, [Swarm](https://github.com/openai/swarm/tree/main), and is also [available in Python](https://github.com/openai/openai-agents-python). The SDK provides:

- **Agents**, which are LLMs equipped with instructions and tools
- **Sandbox agents**, which pair agents with filesystem workspaces, shell commands, file editing, snapshots, and sandbox session state. Isolation depends on the selected sandbox client and configuration
- **Voice agents**, which support low-latency spoken interactions with tools, guardrails, handoffs, and conversation history
- **Agents as tools and handoffs**, which allow agents to delegate to other agents for specific tasks
- **Guardrails**, which validate agent inputs

## Why use the Agents SDK

Two principles guide the SDK's design:

1. Enough features to be worth using, but few enough primitives to make it quick to learn.
2. Works out of the box and lets you customize exactly what happens.

Here are the main features of the SDK:

- **Agent loop**: A built-in agent loop that handles tool invocation, sends results back to the LLM, and continues until the task is complete.
- **Voice agents**: Automatic interruption detection and context management for spoken interactions.
- **TypeScript-first**: Orchestrate and chain agents using native TypeScript language features, without needing to learn new abstractions.
- **Guardrails**: Run input validation and safety checks in parallel with agent execution, and fail fast when checks do not pass.
- **Function tools**: Wrap a function with `tool()` and a parameter schema. Zod and supported Standard Schema values provide local argument validation.
- **MCP server tool calling**: Built-in integration that exposes tools from MCP servers to agents alongside function tools.
- **Sessions**: A persistent memory layer for maintaining working context within an agent loop.
- **Human in the loop**: Built-in mechanisms for involving humans across agent runs.
- **Tracing**: Built-in tracing for visualizing, debugging, and monitoring workflows, with support for the OpenAI suite of evaluation, fine-tuning, and distillation tools.

## Installation

[Add the alpha SDK packages to your application](https://github.com/openai/openai-agents-js/blob/feat/codex-harness/examples/codex/guides/installation.md#add-the-sdk-to-an-existing-application) to run the classic examples on this page. The installation guide's manifest includes Zod 4.

## Choose your starting point

Choose the runtime before changing imports:

| Start with | Use it when | Notes |
| --- | --- | --- |
| `@openai/agents` | You are building a native v1 app or moving a v0 workflow directly to native v1. | Start with the [native installation guide](https://github.com/openai/openai-agents-js/blob/feat/codex-harness/examples/codex/guides/installation.md) and use examples that match your installed release. |
| `@openai/agents/classic` | You need to keep a classic workflow running while you stage its migration. | Includes the classic OpenAI provider setup. Use `@openai/agents/classic/sandbox` for classic sandbox workflows. |
| `@openai/agents-realtime` | You need the standalone Realtime API. | You can also use `@openai/agents/realtime`. Realtime is separate from the text-agent migration. |
| Lower-level packages (`@openai/agents-core`, `@openai/agents-openai`, `@openai/agents-extensions`) | You need lower-level composition, custom provider wiring, or specific integrations. | Most new users can ignore these until they have a concrete need. |
